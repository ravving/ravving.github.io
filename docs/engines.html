    Under the hood / docs/engines.md

    The engines

    Every engine ravving plays, the port facts it relies on and what was measured.

    What ravving relies on for each engine, where each fact comes from, and what was measured on the device. The port facts come from the engine mods' research (~/Coding/<engine>_mod/docs/ RESEARCH.md, decoded from each engine's own source); read the mod before changing an engine's engine.controls in data/kits.json or its MODS profile in data/engines.json. Audited 2026-10-05.

    The MODS: one profile per engine (data/engines.json)

    What a page lets the user tweak of an engine (its SOUND MODIFIERS, the MODS cards, and its expressions, such as the lead ribbon's vibrato) is the engine's, not the machine's: one profile per engine in data/engines.json, found by the engine itself (type, and for jalv the plugin uri; EngineProfiles). Every source that plays an engine shows its knobs, on any machine:

    Profile Engine Shown for
    tal-noisemaker TAL-NoiseMaker (jalv) CHORDS' own synth
    nekobi Nekobi (jalv) BASS' own synth
    calf-monosynth Calf Monosynth (jalv) LEAD's own synth, BASS' 808 · Monosynth source
    fluidsynth FluidSynth every soundfont source (one set for all of a machine's soundfonts: its knobs are offsets to the preset's own sound)
    • A source starts its knobs where its own engine.controls put those ports (the 808's cutoff 400 Hz shows as the CUTOFF knob at 400), so loading a source never changes its sound; without such a control a knob starts at the profile's default.
    • The project keeps each set apart: sound (the own engine's), sourceSound (the soundfonts'), sourceSounds (each other plugin source's, by name); AUTO lanes are sound/…, source/… and sources/<source>/….
    • An engine with no profile shows no MODS. A machine or a source that brings its own sound in kits.json keeps it (a special case; the profile is the rule).
    • Checked against the engines' real ports, twice. On the laptop, tools/check-engines.py (ctest -R engines) checks every knob, choice, expression and kits.json control against the plugins' ports, ranges included, from tests/data/lv2-ports.json. Run tools/check-engines.py --refresh to read them again from the device's lv2info after adding an engine or upgrading plugins. On the device, when an engine starts, SoundEngine::hasControl() checks the MODS of the source playing, and a knob on a control the engine lacks is an issue in the issues centre ("BASS MODS: Calf Monosynth lacks 1 of their controls").

    Adding an engine's MODS: add its profile to data/engines.json (the cards as SoundControls reads them: symbol, min, max, default 0..1, "curve": "log", or choices for a switch), refresh the ports if it is a new plugin, run tools/check-engines.py, then hear each knob on the device (device.sh call <machine>.activeSound setValue CARD KNOB 0..1).

    Nekobi: BASS (track 3)

    http://distrho.sf.net/plugins/Nekobi, a TB-303 clone. Research: nekobi_acid_mod.

    Fact What ravving does
    waveform: the plugin's own labels are wrong: 0 renders a square, 1 a sawtooth WAVE switch: SAW = 1, SQR = 0
    decay is a rate: higher % = shorter (τ 2.3 s at 0 %, 42 ms at 100 %) DECAY runs 100 → 0, so turning it up lengthens notes
    accent is velocity > 90 (forced short decay, filter "wow" from resonance) plain 80, accent 127
    glide is always on (τ ≈ 13 ms) when notes overlap SLIDE = the note lasts 1.5 steps
    cutoff 0–100 % ≈ 0–5 kHz (capped ~6.5 kHz), resonance 0–95 %, env_mod, accent, tuning ±12 CUTOFF, RESO, ENV MOD, ACCENT, TUNE as LV2 ranges
    volume is linear (v/100); Zynthbox's jalv wrapper pins it, ravving's jalv does not volume 100

    Measured: ~1 % CPU; the bass track ~0.067 RMS playing.

    TAL-NoiseMaker: CHORDS (track 4)

    http://kunz.corrupt.ch/products/tal-noisemaker. Research: noizemakr_mod.

    Fact What ravving does
    every port is a bare 0..1; enums quantise as floor(v·(n−1) + 1.5) (1-based): write i/(n−1) voices 1 (6 voices), portamentomode 1 (On: chords glide too), lfo1destination 1/7 (Filter), lfo1waveform 0 (sine), transpose 0.5 (0 oct), filtertype 0 (LP 24 dB; its den is 11)
    osc1waveform: Saw, Pulse, Noise; osc2waveform: Saw, Pulse, Triangle, Sine, Noise WAVE: SAW, JUNO (pulse, osc1pw 0.75), SQR (pulse 0.5), TRI (osc 2)
    lfo1amount is bipolar and cubic: (2(v − 0.5))³, 0.5 = none LFO knob spans 0.5 … 1
    lfo1rate = (e^(0.2 + 3v·ln20) − 1) / 19 Hz 0.3 ≈ 0.9 Hz, a slow sweep
    envelopes are one-poles, very steep: release 67 ms at 0.3, 0.5 s at 0.45, 1 s at 0.5, 3.5 s at 0.6, 12 s near 1; attack 16 ms at 0.15, 0.77 s at 0.45 (computed with the mod's own formulas; its summary table is off) ATTACK spans 0 … 0.55 (3.6 ms … 3.2 s), LENGTH 0.15 … 0.65 (10 ms … 5.8 s)
    chorus1enable, chorus2enable (the Juno chorus I / II) CHORUS switch OFF / I / II
    detune, cutoff (log inside the engine), resonance, portamento SPREAD, CUTOFF, RESO, GLIDE
    volume's curve is undocumented; measured steeper than linear (0.55 → 0.51 RMS, 0.25 → 0.068) volume 0.25
    256 factory presets in the bundle's presets.ttl (78 leads, 53 basses, 34 FX, 28 drums, 26 pads, 15 arps, 13 keys, 7 chords: the name's prefix), each with its port values next to the JUCE state (the mod's research reached them only through the programs extension, which jalv does not surface) SOUND ▾ on CHORDS loads one by setting its ports (Machine::loadSoundPreset), keeping voices, volume, transpose; the SOUND MODIFIERS follow it (SoundControls::adopt)

    Measured: ~1.5 % CPU holding a 4-note chord, ~6 % playing; the chords track ~0.07 RMS.

    Calf Monosynth: LEAD (track 5)

    http://calf.sourceforge.net/plugins/Monosynth. Research: calf_monosynth_mod (+ its engine-symbols.txt).

    Fact What ravving does
    two envelopes: EG1 → cutoff (env2cutoff, default 8000 cents), EG2 → amp (adsr2_amp = 1) LENGTH drives adsr2_r; adsr2_s 1 (a held note sustains); ENV is env2cutoff 0 … 4800 cents
    logarithmic ports: cutoff, every EG time, portamento, LFO rates CUTOFF 300 … 9000 Hz, GLIDE 1 … 400 ms, LENGTH 10 … 3000 ms with "curve": "log"
    o1_wave 16 waves: 0 Sawtooth, 1 Square, 3 Sine, 4 Triangle… WAVE: SAW, SQR, SIN, TRI; o12_mix 0 (osc 1 only)
    legato 0 Retrig, 1 Legato, 2/3 finger modes; pbend_range up to 2400 cents legato 1 (overlapping notes glide), pbend_range 1200
    one LFO1 drives lfo2pitch and lfo2filter vibrato only: lfo_rate 5.5 Hz, lfo2pitch played by the ribbon (expression vibrato, 0 … 60 cents)
    master 0..1 (Zynthbox's wrapper pins it; ravving's jalv does not) master 0.3

    Measured: ~0.5–1 % CPU; the lead track ~0.086 RMS playing, ~0.16 while the ribbon plays.

    FluidSynth: DRUMS 1–3 (tracks 0–2)

    FluidSynth 2.4.4 (a process, not an LV2), one per drum machine with its kit's soundfont. Research: fluidsynth2_mod.

    Fact What ravving does
    level CCs (7, 11) and velocity attenuate as 40·log10(v/127) dB, twice the usual law row levels go through velocity (level 0.8 → velocity 100 ≈ −4 dB; accent ×1.27 → 127)
    reverb / chorus CCs are sends of at most 20 %; the effects' settings have no CC none sent; measured: with FluidSynth's own reverb and chorus on or off, a snare's tail is silent either way (CC 91 stays 0 and the 909 kit sends none): the drums carry no hidden reverb
    started like zynthbox-qml: -g 1, synth.polyphony=64, MMA bank select the same command line

    The drums' SOUND MODIFIERS are the kit's own (engines.json's kitSound, EngineProfiles::resolveKit): TONE (CUTOFF, RESO), SHAPE (ATTACK, LENGTH: the release) and PITCH (TUNE in semitones, FINE in cents), SF2 generator offsets sent as NRPNs like the soundfont sources' MODS. A kit is one soundfont on one channel, so they act on the whole kit; per drum would need a channel per row.

    Acoustic kits inside a General MIDI font (kits.json presetKits, the picker's ACOUSTIC group): a kit's path may name one preset of a soundfont, <file>#<bank>:<program>, and after it choose a row's key, ?CYMBAL=51&HAT=44. FluidR3's kits sit at bank 128 (Jazz 32, Brush 40, Standard 0, Room 8) and keep the General MIDI map, so a key whose sample name says nothing ("Md Studio", its toms) takes its GM role. "Jazz · ride" and "Brush · ride" put the ride (51) on CYMBAL and the hi-hat foot (44) on HAT (shown as PEDAL); the plain "Jazz · crash" keeps the crash, for breaks. FluidSynth gets the file and the bank and program; the path with its choices is what a project saves.

    SamplerSynth: SAMPLE KING (track 6)

    libzynthbox's own sampler: no process, clips (ClipAudioSource) played in the audio thread. Facts from libzynthbox's source (SamplerSynthVoice.cpp, ClipAudioSourceSliceSettings.cpp, AudioLevels.cpp) and measured on milo.

    Fact What ravving does
    a slice's envelope defaults to {attack 0, decay 0, sustain 1, release 0} only the release is set (8 ms, the choke's fade)
    every voice faded in over ~165 ms (started at gain 0, ramped 0.0001 a frame since b487712): a 0 dBFS kick peaked at 0.096 patched in libzynthbox (a voice starts at its gain; only aftertouch changes ramp), installed on milo; reported in ~/Coding/libzynthbox-bug-reports.md
    a one-shot retriggered on the same clip and slice stops its previous voice (SamplerSynthVoice.cpp:392) the slots choke themselves as easyrave's do; no exclusivityGroup needed
    one-shots cannot play backwards (only loops and granular do) REVERSE plays a reversed copy of the file
    a track's channel_N-sampleM ports exist only while a clip is registered on that slot wired per loaded slot (setSampleOutputs)
    ClipAudioSource::play(…, velocity): 64 is unity gain previews play at 64 on the global lane
    AudioLevels' track gain (a machine's VOL) runs −40…+20 dB, 0 at gainAbsolute 0.667; the lane's sends leave before it the sends are scaled by VOL's gain in ravving (TrackEffects::setSendLevel)

    Measured: a 0 dBFS kick at velocity 100 peaks 19 ms after its onset (the drum's own shape) once patched.

    The audio input (HiFiBerry DAC+ADC Pro, PCM1863)

    Fact What ravving does
    the five jacks, left to right: 1 headphones, 2–3 line outputs (speaker icon), 4–5 inputs (mic icon); jack 4 is the left channel (ADC input VINL1), jack 5 the right (a plug not fully home showed up on the other channel) MIC and GUITAR record the jack with the signal (activeJack: picked between takes when one jack is 10 dB over the other and above −45 dBFS; mixing both added the empty input's noise, audibly), so either jack works; LINE is stereo; INPUT lights each jack's level (AudioLevels' capture meter, rewired to the real inputs); monitor on headphones in jack 1
    the HiFiBerry's JACK capture ports are named like a Dummy card's, and which gets the serial suffix changes between boots found by the card each start (InputPorts)
    input noise is mostly the room around the cables: a switched-off mic on jack 4 read −52 dBFS (in bursts) with the user at the desk, −75 dBFS once they left (ravving stopped or playing alike); screen brightness, mic bias, one or two ADC inputs made no difference beyond the run-to-run spread — (a ground loop through the USB-Ethernet link to a charging laptop is the usual suspect)
    the ADC's input mux is ADC Left/Right Input; ADC … Capture Source did not change what was heard the selection is left as Zynthbox sets it
    PGA −12…+40 dB in 0.5 dB steps (PGA Gain Left/Right), mic bias on/off; Zynthbox selects VINL2 + VINL1 MIC +30 dB with bias, GUITAR +10 dB (a strummed electric peaked −5 dBFS at +18), LINE 0 dB; the selection left as Zynthbox sets it
    the open input's noise is −69 dBFS at +30 dB a take under −50 dBFS is refused, not normalised into noise
    input → monitor ≈ 11–16 ms (256 frames at 48 kHz); the capture node follows the output's clock (no resampling) MONITOR through track 9's lane with its own LEVEL

    The input effects (data/input-fx.json)

    Ports from lv2info on milo (2026-10-05); the chains are in the presets file. A silent mic on milo (+40 dB PGA) measured −48 dBFS of noise in bursts, mostly under 300 Hz (27–28 Hz, 162 Hz), 16 dB over the empty input: CLEAN cuts it with a 24 dB/octave high-pass and a gate.

    Plugin Facts the presets rely on
    Calf Compressor stereo; threshold is linear (0.06 ≈ −24 dBFS), ratio 1–20, attack/release ms, makeup 1–64 (×)
    Calf Saturator stereo; drive 0.1–10, blend −10…10, mix 0–1, pre/post high- and low-pass in Hz
    Calf Multi Chorus stereo; amount (wet) and dry 0–4, voices 1–8, mod_rate Hz, mod_depth ms
    Calf Vintage Delay stereo; timing 0 = BPM (from the bpm port), subdiv 4 with time_l/time_r 3/4 = a dotted eighth / a quarter; amount (wet) 0–4, feedback, medium 1 = tape
    Calf Ring Modulator stereo; mod_freq 1–20000 Hz (20–600 for a robot), mod_amount 0–1, mod_mode 0 = sine
    Calf Filter stereo; mode 4 = 24 dB/octave high-pass, 7 = 12 dB band-pass; freq Hz, res 0.707–32
    Calf Gate stereo; threshold linear (0.01 = −40 dBFS), range the most it closes (0.03 = −30 dB), ratio, attack/release ms
    Dragonfly Plate stereo; dry_level and its wet level (the port is named early_level) 0–100, decay s, predelay ms, low_cut/high_cut Hz
    MaPitchshift (DISTRHO) mono in, two outs; ratio 0.25–4 (0.5 = an octave down), window ms, blur; no dry mix
    SwankyAmp stereo, its own cabinet (cabonoff); every port 0–1 (preampdrive, powerampdrive, inputlevel, outputlevel…)

    A mono plugin in the chain takes both sides summed and feeds both sides of what follows (JackWiring::setInputChain). Measured with several presets started (a dozen jalv processes): about 1–2 % CPU each over 3 s (top), the busiest 5.6 %; load average 1.7–2.7 on the Pi 5's four cores.

    Effects

    Calf Saturator (DRIVE), Calf Crusher (CRUSH), Calf Phaser (PHASER), Dragonfly Room (REVERB), TAP Echo (DELAY) have no mods; their ports come from lv2info and were calibrated by measurement (tools/lv2probe.sh, see debugging.md). The beat repeat (STUTTER, LOOP) is ravving's own JACK client.

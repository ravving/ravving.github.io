    The designs / docs/mpc-sampler-plan.md

    The PAD SAMPLER

    The MPC model distilled, the pads on the step keys, record-to-pad, 16 LEVELS, pad FX, the wave editor.

    A second sampler for page 5, next to SAMPLE KING, modelled on the Akai MPC: 16 pads on the device's 16 step keys, the MPC's pad layout on screen, the MPC Sample's parameter set as the first scope, and the MPC Standalone OS's drum tracks as the horizon to scale up to. The two samplers are mutually exclusive: the one on screen plays, the other is silent, as a first rule; later they may play together.

    Written 2026-10-07 from a cross-reading of three Akai sources, the ravving code, libzynthbox and the plugins on the device. Section 7 is the plan; sections 1–6 are what it rests on.

    The MPC Sample is the model for the first versions: it is a 16-pad sampler with exactly our knob count, and its whole feature set fits one screen. The OS guide tells where each feature grows when scaled up.

    2. The MPC model, distilled

    Pads. 4 × 4, numbered from the bottom left: row 4 = 13 14 15 16, row 3 = 9 10 11 12, row 2 = 5 6 7 8, row 1 = 1 2 3 4. Banks A–H, one on screen; PAD BANK cycles them. A pad holds one sample (MPC Sample) or up to four layers (OS). Pads light: loaded, playing, selected, muted (red), 16 Levels (velocity ramp).

    Sample Mode: the per-pad parameters, three per tab, one knob each:

    Tab (button) K1 K2 K3
    Trim (B1) Start 0–100 % End 0–100 % Loop point 0–100 %
    Mix (B1) Volume −∞…+6 dB (SHIFT: kit volume) Pan 50L–C–50R
    Amp Env (B1) Attack 0–127 Decay (one shot) / Release (note on) 0–127; SHIFT: decay from Start or End Vel Sens 0–127
    Tune (B2) Semi −24…+24 Fine −90…+90 cents Warp (off / 50–200 % / Seq), time-stretch or pitch
    Play (B2) Polyphony Mono / Poly Mute group Off, 1–16; SHIFT: Pad Link Trigger offset 0–100 %
    Filter (B3) Cutoff 0–127 Reso 0–127 Type Off, Classic, LPF2/4, HPF2/4, BPF2/4
    Filt Env (B3) Attack Decay / Release Depth

    Pad Play (toggles on the selected pad): Chop (threshold / regions 4-8-16 / manual slices, each slice on a pad; extract, split, merge), Note On (plays while held; else One Shot), Loop (loop point → end; Loop Lock ties it to Start), Reverse, Mute (pads mute instead of trigger; unmute all), 16 Levels (the selected pad on all 16 with velocity, filter or tune ramping; original tune on pad 4).

    Sample Record. Source (mic, line L/R, resample, USB), monitor off/auto/on, threshold, length free or the sequence; tap a pad to arm it, record, tap again to stop; the take lands on that pad trimmed; RECALL grabs the last 25 s of input.

    Sequence Mode. Sequences on pads (light green when holding events), 1–128 bars, Q (record quantize), RT Swing, count-in, metronome off/on/record, BPM per sequence or global, record then overdub, SHIFT + undo, erase a pad's events, RECALL the last loop's playing; Step Edit lists events per step with velocity and timing nudge; half/double length and speed; resample a sequence to a pad; Song Mode strings sequences.

    Not for us (yet or ever): Pad FX / Flex Beat / Knob FX (ravving has its LIVE FX), compressor menu (ravving's SOUND EFFECTS), MIDI/CV config, project pages, USB audio.

    4. What libzynthbox gives, per MPC parameter

    ClipAudioSourceSliceSettings (the root slice, and up to 1024 slices per clip) carries:

    MPC libzynthbox Note
    Start, End startPositionSamples, lengthSamples as SAMPLE KING's trim
    Loop, loop point playbackStyle = LoopingPlaybackStyle, loopDeltaSamples (loop start past the slice start), loopCrossfadeAmount loop lock = delta 0
    One Shot / Note On OneshotPlaybackStyle (ignores note off) / NonLoopingPlaybackStyle (stops at note off, release applies)
    Reverse no backward one-shot: a reversed copy of the file (AudioFile::writeReversed, cached) as SAMPLE KING does granular/loop styles can run backwards; not for one-shots
    Volume, Pan gainHandler (dB), pan −1…1
    Semi, Fine pitch (semitones, fractional: fine = cents / 100)
    Attack, Decay/Release, (Sustain) adsrAttack/Decay/Sustain/Release one shot: sustain 0 and decay; note on: sustain 1 and release
    Vel Sens velocity scaling in the machine (liveVelocity) + velocityMinimum/Maximum
    Mono / Mute group exclusivityGroup (−1 none; same group = last played silences the rest) mono = a pad in its own group cuts itself; mute group 1–16 = shared group ids
    Pad Link (two pads from one) the machine sends both notes (liveNotes(key) returns two) as ChordMachine plays a chord
    Trigger offset not native: start position moved forward is a different thing; defer
    Filter type, cutoff, reso ClipAudioSource.equaliserEnabled + equaliserSettings bands: JackPassthroughFilter LowPass/HighPass/BandPass types, frequency, quality a per-pad 6-band EQ with LP/HP bands set as the filter; no Classic model
    Filter envelope none defer; could ride on automation later
    Warp / time stretch timeStretchStyle, speedRatio, bpm, autoSynchroniseSpeedRatio phase 4
    16 Levels 16 virtual pads: the same clip at 16 velocities, or 16 slices with different pitch the machine builds the map; clips stay one
    Chop slices: sliceCount, insertSlice, each slice its own key zone → a slice per pad the OS's "convert slices to pads" is native here
    Layers (4 per pad, velocity/cycle/random) several clips on one key zone with velocityMinimum/Maximum ranges; cycle/random in the machine phase 4
    Record, Recall InputRecorder; AudioLevels' port recorder (scheduleStartRecording); a 25 s ring buffer is not there recall = phase 4, needs a continuous recorder
    Resample MixRecorder (master to WAV) → load onto a pad phase 3
    Note Repeat SyncTimer-timed retrigger from the machine while a pad is held phase 3

    Other engines on the device were checked and ruled out: the Fabla LV2 (16-pad sampler) runs 1.4 on the device, which cannot load samples; sfizz, samplv1, drumkv1 and LinuxSampler are not installed. libzynthbox's SamplerSynth is the engine, as for SAMPLE KING.

    5. The one constraint: samples per track

    SamplerSynth gives each sketchpad track 10 sample sub-channels (5 slots × 2 rows, each with its own JACK ports), and SketchpadTrack.samples is a list of 10 in zynthbox-qml's model. SAMPLE KING's banks are 8 slots for that reason. 16 pads exceed it.

    Two ways, decided by a spike at the start of phase 2:

    • A. One track, 16 clips (preferred). PatternModel::setClipIds accepts any list length, and SamplerSynth plays every registered clip whose key zone holds the note; a clip's slot/row only chooses which sub-channel's ports it renders to. Pads 11–16 would share sub-channels with pads 1–6, which only means they share output ports, and all of them go to the same track lane anyway. To verify: 16 clips on track 7 with slots i % 5, rows (i / 5) % 2, every pad audible on its own note, no voice stealing between pads sharing a sub-channel, and JackWiring::setSampleOutputs wiring the 10 ports.
    • B. Two tracks (fallback). Pads 1–8 on track 7, 9–16 on track 8, each with its own PatternModel; the machine mirrors bars, Q and the playhead onto the second pattern and routes a pad's hits to its track. More code in Machine (which is one-track by design).

    Tracks 7 and 8 are free (0–2 drums, 3 bass, 4 chords, 5 lead, 6 SAMPLE KING, 9 the input monitor).

    6. Design

    6.1 Page 5 hosts two samplers

    As DRUMS hosts three machines: SamplerPage gets a Repeater over the two panels, ravving.samplerMachine (0 SAMPLE KING, 1 PAD SAMPLER) picks the one on screen, key 5 again cycles, the header's INSTRUMENTS strip gets a second chip (SAMPLER · PADS), ◀ ▶ keep their panel meaning (SAMPLE KING's banks, the PAD SAMPLER's tabs), so the switch is key 5, the chips, or the nameplate. Session.liveMachine, stepLeds, the big-knob volume and MODE follow the panel on screen, as on DRUMS.

    Mutually exclusive: Studio.activeSampler names the one that plays; the other is paused (its pattern silent) and muted (its lane down), its clips stay loaded so switching back is instant. Switching the panel on screen switches the active one. Later both can play when the rule is lifted (nothing else depends on it).

    6.2 The PAD SAMPLER on screen (the dummy UI, phase 1)

    Inside the usual MachineModule (strip with nameplate, PAN, VOL, REC, ❚❚, LIVE, S, M; SOUND MODIFIERS collapsed; SOUND EFFECTS chain), the editor is:

    ┌───────────────────────────────────────────────────────────────────────────────┐
│ ● PRESET  ‹ 1/1 ›  Q  + −  AUTO  ↶ ↷  CLEAR         BANK A B C D   ERASE COPY │ toolbar
├──────────────────┬────────────────────────────────────────────────────────────┤
│ 13  14  15  16   │  A03  Kick-808        ♩ ← ⟲ 16   ▁▂▃▅▇▅▃▂▁ waveform ▁▂▃    │ screen
│  9  10  11  12   │  [start]──────────[loop]──────────[end]                     │
│  5   6   7   8   │  TRIM · MIX · AMP ENV   |  TUNE · PLAY  |  FILTER          │ tabs
│  1   2   3   4   │   (K1) START   (K2) END   (K3) LOOP        ⟨3-knob card⟩   │
├──────────────────┴────────────────────────────────────────────────────────────┤
│ PAD 3 · Kick-808   ▢▢▢▢ ▢▢▢▢ ▢▢▢▢ ▢▢▢▢   the selected pad's 16 steps          │ lane
│ 1 ····x···x·····  2 ··x···x···x···  … 16 ················ (overview, tap = select) │
└───────────────────────────────────────────────────────────────────────────────┘
    • PadGrid (new): 4 × 4 in MPC order, each pad: number, name (elided), a 16-dot mini step row (its hits in the bar on screen), colour = pad colour when loaded, dim when empty, red when muted, accent outline when selected, white flash while held or hit. Tap selects and auditions (hold to hear, as the MPC), ERASE + pad clears it, COPY + pad copies.
    • SampleScreen (reused): the selected pad's waveform with START / END / LOOP handles, the pad's icons (note on ♩, reverse ←, loop ⟲, 16 levels), the take's time and meter while recording into it.
    • Tabs: three ParamCards in a ParamCardRow (TRIM, MIX, AMP ENV | TUNE, PLAY | FILTER, FILT ENV), one visible group of three at a time; ◀ ▶ with the editor focused cycle the tabs (B1/B2/B3), the three knobs drive the card (K1–K3), with pick-up on the Z2_V5B pots exactly as the MPC describes for its own absolute knobs. Switch-type values (filter type, polyphony, mute group) use WaveCycler-style choice knobs.
    • Pad Play chips on the screen's edge: NOTE ON, LOOP, REVERSE, MUTE, 16 LEVELS, CHOP (CHOP real since phase 5).
    • Lane: the selected pad's 16 steps as a drum row (tap to write; the 16 step keys write it with LIVE off, as every machine), with the accent key, plus the overview of all pads. This is the MPC's Step Edit shown as a grid; a per-step event list is not needed.
    • Hardware: step keys = pads 1–16 while LIVE (stepKeysArePads), else steps of the selected pad; knobs 1–3 = the tab's K1–K3; big knob = volume (page) or the pad selection when the pad grid has the focus; ◀ ▶ tabs; ▲ ▼ walk lane → pad grid → screen → strip → header (and the SOUND sections when open), ALT + ▲ the header; MODE = LIVE; RECORD = a take into the selected pad; SELECT on a pad = audition; BACK = the editor.
    • LEDs: the 16 step keys show the pads' colours while LIVE (held = white), the lane's steps otherwise; ◀ ▶ lit (tabs).

    6.3 The backend (phase 2)

    PadSamplerMachine : Machine (src/backend/padsamplermachine.{h,cpp}), kind "pads" in kits.json (track 7, baseNote 36 so pad 1 = C1 = GM kick, pads up chromatically; an external keyboard or pad controller plays them as any MPC does over MIDI), pads-presets.json (charts "1"–"16", as the sampler's).

    struct Pad {                      // one pad of one bank, everything the MPC Sample keeps
    QString path; QString name;   // the sample (empty = none)
    qreal level{0.8}; qreal pan{0};
    int semi{0}; int fine{0};     // tune
    qreal start{0}, end{1}, loop{0};  // fractions of the file; loop lock = loop == start
    bool looping{false}, reverse{false}, noteOn{false};
    bool mono{false}; int muteGroup{0}; int link{0};
    int attack{0}, decayRelease{0}, velSens{127};
    int filterType{0}; int cutoff{127}; int reso{0};
    bool muted{false};
    QColor color;                 // the pad's colour, from a palette of 16
};
struct Bank { QList<Pad> pads /*16*/; QHash<int, QSet<int>> hits; QSet<int> accents; int bars{1}; };
    • Machine gives the pattern, bars, Q, playhead, presets, LIVE, takes, undo/redo, level, pan, effects, mute, ❚❚. The machine adds: pads (QVariantList for QML), bank, the selected pad, loadSample(pad, path), clearPad, copyPad, setPad<Param> for each parameter, audition(pad), erasePad(pad) (its hits), halveSequence(), doubleSequence(), sixteenLevels(type) on/off, noteRepeat(division) (phase 3).
    • Clips: one ClipAudioSource per loaded pad (option A: all on the machine's track; option B: track 7/8 by pad), configured from the Pad on every change: key zone and root note = the pad's note, playback style (one shot / note on / loop), start / length / loop delta, pitch = semi + fine / 100, gain / pan, ADSR (one shot: A, D, S 0, R short; note on: A, S 1, R), exclusivity group (mono: 100 + pad; mute group: the group; none: −1), the EQ bands for the filter. Reversed files rendered once in a worker, cached by path hash (SAMPLE KING's code, moved into a shared helper so both samplers use it).
    • Velocity: liveVelocity(pad, accented) = level × (vel sens applied to the pad's measured force where a controller gives one; the step keys give full level) × accent, −1 when muted; revoice() rewrites the pattern as the drums do.
    • Hits: placeHit(position, pad, accented) writes the pad's note; liveNotes(pad) returns the pad's note, plus its linked pad's; the take records live hits through the existing TakeRecorder (count-in, punch-in, overdub).
    • Takes into a pad: studio.input.record() as SAMPLE KING, the processed take loaded on the armed pad with the last burst as its trim.
    • State: state() carries bank, banks (pads, steps, accents, bars); restoreContent reloads it; projects, presets and undo come with Machine.
    • Exclusivity: Studio::setActiveSampler(key): pause + mute the other, publish activeSampler; saved with the session.

    6.4 Quality gates (every phase)

    From docs/quality.md and the ravving-quality skill: clang-tidy / clazy clean on the new files; startup time unchanged (the second sampler loads its clips lazily, after the first frame, like the pages); the QML profiler on the pad grid (16 pads × 16 dots must not bind per frame: one hits list, repainted on stepsChanged); the screenshot tour gets the PAD SAMPLER screens (src/main.cpp steps); ravving.cuia.debug traces for the ▲ ▼ walk; the local build loop (tools/device.sh deploy), never the AppImage, until a release.

    7. What the user wants first (2026-10-07)

    Seven points, in the user's words, that set the order of the phases:

    1. Record onto each pad quickly from whatever is on the jack: guitar, a turntable, a mic.
    2. Loop the recorded sound on its pad, or not.
    3. The pads in a sequence, looping like the other instruments' views.
    4. Live effects on the playing pad: a scratch, an echo, reverse, skip forward, other common ones (the MPC's Pad FX / Flex Beat, which this plan had left out: back in).
    5. Loop all of them, or live mode: while the other views play, a long press on a pad leaves it looping, a single tap plays it once.
    6. A wave editor shared by both samplers to chop audio.
    7. Per-pad sound parameters, effects and filters.
    8. Smart recording: a take that stops by itself when the sound stops (strum a chord on the guitar, the pad has it), so a pad is recorded with one press.
    9. Auto-chop a music snippet across the 16 pads, each pad then playing like a note.

    So the first backend delivers 1, 2, 3, 5 and 8; the next 7 and 9; then 4 and 6.

    Reference implementations the user pointed at (cloned under ~/Coding/refs/): vmpc-juce (an MPC2000XL emulator in C++/JUCE: the sequencer, 16 Levels, chop and pad logic as the original did them), giada (a C++ loop machine: sample channels with loop / one-shot modes and an action recorder, close to point 5), MPC-Sample-Toolkit (Python, the MPC Sample's file formats and kits; anything used from it is ported to C++).

    8. Plan

    Phase 0 — this document. Decisions to take (defaults in bold if not answered): 1. Clips: option A, one track after the spike; B if it fails. 2. Name on the plate: PAD\nSAMPLER (role PADS; "MPC" stays in the docs, not on screen). 3. Default on key 5: SAMPLE KING stays first (0), the PAD SAMPLER is 1. 4. The lane: selected pad's 16 steps + the 16-row overview (not a 16-row StepGrid: rows would be 24 px). 5. Pad colours: a fixed 16-colour palette by pad number (as MPC pad colour mode), the selected pad's colour lighting its step key.

    Phase 1 — the dummy UI (QML only, no backend; PadState.qml in memory like PatternState / EffectsState): 1. SamplerPage hosting the two panels, ravving.samplerMachine, the header chip, key 5 cycling, the exclusivity rule stubbed in Session. 2. PadSamplerPanel.qml (MachinePanel) with PadGrid.qml, the reused SampleScreen, the tab cards, the Pad Play chips, the lane and overview. 3. The hardware walk (pads, tabs, knobs with pick-up, ▲ ▼ chain, LEDs) verified with the trace and screenshots on the device; the screenshot tour step. 4. Docs: architecture.md components table, this plan's status.

    Phase 2 — the backend: the user's points 1, 2, 3 and 5. 1. The spike (§5), then PadSamplerMachine with bank A: load / clear / copy a pad, and record to a pad from the input: select a pad, ● REC (or hold RECORD and tap a pad), ● again to stop; MIC / GUITAR / LINE come from InputRecorder's set-up (INPUT button), the take lands on the pad trimmed to its last burst. Trim (start, end, loop point) and Mix (level, pan) so a take is usable at once. Smart stop (point 8): the take arms on ● REC and starts when the input crosses the threshold (the MPC's Threshold), then ends by itself once the input has stayed under the threshold for a hold time (0.5 s by default, the SMART chip; the MPC's "Free" length is ● again, "Seq" the sequence's length): InputRecorder already meters the input (level), so this is a state machine on it (armed → recording → done) plus the processing it does today (last burst = trim). 2. Loop or one-shot per pad (LOOP chip: LoopingPlaybackStyle from the loop point; NOTE ON: plays while held) and Reverse. 3. The sequence: everything Machine has (the lane, bars, Q, presets, undo, the take with count-in and overdub), plus erase pad, half / double sequence. 4. Live play: while LIVE, a tap plays a pad once (its one-shot, or one pass of its loop), a long press (> 400 ms) latches it looping until it is tapped again, lit while it loops, over whatever the other machines play; a looping pad that is not in the pattern keeps looping across bars (a clip started looping on SamplerSynth, as ClipAudioSource::play(forceLooping) does), and STOP ends them all. 5. kits.json entry, presets file, Studio factory branch, wiring (setSampleOutputs), exclusivity with SAMPLE KING, state save/restore, projects. 6. Quality pass: clang-tidy / clazy, startup time, QML profile of the pad grid, the full screenshot tour, the sound verified by pw-record on GlobalPlayback as the drums were.

    Phase 3 — point 7, the per-pad sound: Amp Env (attack, decay/release, vel sens), Tune (semi, fine), Play (mono/poly, mute group, pad link), Filter (type, cutoff, reso via the clip's EQ bands), per-pad effects (the clip's compressor and EQ as the pad's insert; the track's SOUND EFFECTS stay the kit's), Mute / unmute all, 16 Levels (velocity, tune, filter), kit volume and tune. Point 9, first form: 16 LVL · TUNE spreads one sample over the 16 pads as 16 pitches (the MPC: the original on pad 4, a semitone per pad), which is "each pad a note" without chopping; with CHROMATIC the pads follow the header's ROOT / SCALE instead of semitones, as the chord keys do.

    Phase 4 — point 4, live pad FX (the MPC's Pad FX / Flex Beat, on the playing pad): ECHO (the track's echo throw, as LIVE FX ECHO), REVERSE (switch the playing pad to its reversed copy from the current position), SKIP (jump forward by a division: restart the voice at position + 1/8 or 1/4 bar), STUTTER (retrigger at 1/16 … 1/64: the Note Repeat engine on the pad), SCRATCH (a speed ramp on the clip, speedRatio with time stretch off, swept down and back as a turntable would; needs a measurement of what SamplerSynth can do live), TAPE STOP (speed to 0), FILTER sweep (the clip's EQ as LIVE FX LO/HI PASS does on the master), GATE (velocity on/off at a division). Held pads (the step keys with ALT, or an FX row of chips on screen) engage them while held, as the MPC's.

    Phase 5 — point 6, the wave editor shared by both samplers: one WaveEditor (a popup over the page, or the screen enlarged) on libzynthbox's WaveFormItem with zoom, start / end / loop handles, zero-snap, normalise, trim (destructive, to a new file), and Chop: threshold / regions 4-8-16 / manual slices (libzynthbox slices, extract / split / merge), then slices onto the pads (the PAD SAMPLER) or the slots of a bank (SAMPLE KING). CHOP on both panels opens it on the selected pad / slot. Point 9, second form: AUTO CHOP takes a snippet (a take, a loaded song excerpt) and cuts it into 16 slices onto the 16 pads in one press: regions (16 equal parts, beat-aligned when the snippet's BPM is guessed: ClipAudioSource::guessBPM) or transients (threshold), each pad then a one-shot of its slice, playable as notes from the step keys or a keyboard.

    Later — towards the OS drum track: banks B–H, layers (up to 4 clips per pad, velocity / cycle / random), warp (time stretch), filter envelope, RECALL (a continuous input ring buffer: a libzynthbox addition), resample the mix to a pad, simultaneous play and mute targets, velocity from MIDI controllers, both samplers playing at once.

    9. libzynthbox gaps: patches, then PRs (or a fork)

    What the sampler needs and libzynthbox does not do today. The rule (the user's, 2026-10-07): fill each gap as a patch against libzynthbox, send it upstream as a PR; if it is declined, keep it in a fork that tracks upstream. Until a patch lands, ravving works around it.

    Gap Where Work-around in ravving Patch
    A track's pattern reads exactly ten sample slots (PatternModel::updateSamples, slotIndices {0..9}; zynthbox-qml's channel has ten) PatternModel.cpp pads 11–16 on a second track (§5) read as many slots as the channel publishes (or 16)
    A sample-trigger pattern plays a note whatever its velocity: the drums' silent velocity (−1) does not silence it (to confirm against zynthbox-qml's own sample tracks) PatternModel / SamplerSynth silenced pads are left out of the pattern honour velocity ≤ 0 as "do not play" for SampleTriggerDestination
    No backward playback for a one-shot (only granular / loop styles run backwards) ClipAudioSource a reversed copy of the file, rendered once (AudioFile::writeReversed) a reverse flag on the slice for every style
    No input ring buffer for the MPC's RECALL (the last 25 s) AudioLevels / the port recorder none (phase 5+) a continuous recorder with a "keep the last N seconds" file
    No per-slice filter with resonance, no filter envelope ClipAudioSourceSliceSettings the clip's EQ bands for cutoff / type (phase 3), no envelope a per-slice SVF (LP / HP / BP, cutoff, Q) with an ADSR on the cutoff
    A slice's playback style change is not applied to a sounding voice (a loop turned one-shot ignores the note-off that follows) SamplerSynth voices the unlatch keeps the loop style for 150 ms voices read the style at note-off
    A non-root slice's own pitch is ignored: a voice transposes by the key's distance to the slice's root note and by the clip's (root) pitch only (SamplerSynthVoice.cpp 552, 780) SamplerSynthVoice 16 LEVELS slices transpose through their root note (whole semitones) apply the slice's pitch in the voice's ratio
    Deleting a ClipAudioSource under a playing voice crashes the audio thread (bug report 15) ClipAudioSource / SamplerSynth ZynthboxBridge::retireClip() free after the audio thread drops the voices

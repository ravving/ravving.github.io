    The designs / docs/sampler-plan.md

    SAMPLE KING

    What easyrave's sampler does, what libzynthbox's gives, and the phases that built page 5.

    The sampler page (page 5), and live voice / guitar effects while recording. Research 2026-10-05 from easyrave's source, libzynthbox's source and the device (milo).

    Status (2026-10-05): phases 1 (playback) and 2 (recording) are built and running on milo; phase 3 (live FX: InputEffects, data/input-fx.json) is built, waiting for the presets to be tuned with a mic and the guitar; phase 4 is next. The decisions below were taken as proposed: 4 banks × 8 slots, takes in /zynthian/zynthian-my-data/samples/my-samples/ravving/ (raw takes kept in ~/.local/share/ravving/takes-raw/), record wet (+ dry later), TAME first. What the build found is in engines.md (SamplerSynth, the audio input) and architecture.md (SamplerMachine, InputRecorder, AudioFile).

    What easyrave's SAMPLE KING does

    • Banks A–D, each with 8 sample slots and its own pattern (a step grid, a row per slot). Switching bank switches kit and pattern.
    • Machine knobs on every slot: LEVEL, CUTOFF, BIT CRUSHER, AUTOTUNE (re-tunes autotuned samples to the song's key when the key changes).
    • Slot editor: a waveform screen with trim handles (start, length), PITCH ±12, REVERSE, ▶ preview, ● record; a LAYER: a second sample in the same slot, fired by the same hit.
    • Playback: a hit plays the trimmed window one-shot; each slot chokes itself (a new hit fades the previous one out in 8 ms instead of stacking).
    • Levels by loudness: each sample is matched by its loudness while it sounds (BS.1770 K-weighting, 100 ms blocks, gated), not by its peak (a vocal and a kick with the same peak were 8 LU apart).
    • A mic take is processed before it becomes a sample: DC removed, 6:1 compression (fast attack, musical release), normalised to just under full scale; the trim defaults to the last burst when a take holds several.
    • KEYS (keys 1–8 play the slots live) and REC (a take of the pattern, count-in first).

    What the device gives us

    libzynthbox's sampler is the engine. SamplerSynth plays ClipAudioSources in real time (JUCE, in the audio thread). Each slot is one ClipAudioSource; its root slice has what every slot feature needs:

    Slot feature ClipAudioSource / slice
    which note plays it keyZoneStart = keyZoneEnd = the slot's note, rootNote = the same (no transposition)
    trim startPositionSamples, lengthSamples
    PITCH pitch (semitones)
    one-shot playbackStyle = OneshotPlaybackStyle
    choke exclusivityGroup (−1 none; a slot in its own group cuts itself)
    level, pan gainHandler, pan (loudness matching sets the gain)
    envelope adsrAttack/Decay/Sustain/Release (a short release = easyrave's 8 ms fade)
    LAYER a second ClipAudioSource on the same key zone: SamplerSynth plays every clip that matches the note
    (later) granular modes, slices, velocity zones, loops

    A ClipAudioSource is built through its exported constructor, the way ravving already makes the metronome clips (ClipAudioSource(path, track, slot, row, registerForPolyphonicPlayback, muted, parent)).

    Routing is already in place. SketchpadTrack (ravving's zlChannel) with trackType "sample-trig" makes the track's PatternModel send its notes to SamplerSynth (SampleTriggerDestination), and its samples list (10 entries, each an object with cppObjId = the clip's id) is how PatternModel registers the clips (updateSamples() → setClipIds()). So a bank = 8 clips in that list + its own pattern; switching bank swaps the list and the pattern. LIVE keys reach SamplerSynth the same way the synths' do.

    REVERSE is not a one-shot option (only granular and loop styles run backwards), so a reversed slot plays a reversed copy of its file, rendered once.

    Waveforms: libzynthbox ships WaveFormItem (QML), which draws a ClipAudioSource's waveform with its own peak cache: no drawing in JS.

    Recording: AudioLevels records any JACK ports to a WAV (addRecordPort(port, channel), setShouldRecordPorts, scheduleStartRecording(delay) sample-accurately on SyncTimer's clock, stopRecording, recordingFilenames): a take can start exactly on the bar after a count-in. AudioLevels also meters the input (captureA/B).

    Files: libsndfile 1.2.2 is installed on the device and the laptop: reading, writing, reversing, the take processing and the loudness measurement run in C++ in a worker thread (QtConcurrent), never on the UI thread.

    The input (milo: HiFiBerry DAC+ADC Pro, PCM186x ADC)

    • JACK ports Built-in Audio Stereo:capture_FL / capture_FR, 48 kHz.
    • PGA gain −12 … +40 dB per channel (amixer -c 3 "PGA Gain Left/Right", 0.5 dB steps), plus the ADC digital volume; input select (VINL1/VINL2, differential) and mic bias (on).
    • So the page can offer input modes: MIC (bias on, PGA ~+20…30 dB), GUITAR (bias off, PGA ~+20 dB, mono), LINE (PGA 0 dB, stereo), with a level meter and a gain knob. (The exact gains are to be set with the user's guitar and mic.)

    Live voice / guitar effects: yes

    Feasible and cheap. The device has every block, and a whole chain costs little: eight effects running on the input (compressor, saturator, multi chorus, phaser, vintage delay, plate reverb, SwankyAmp, pitch shifter) measured under 1 % CPU each on the Pi 5 (4 cores). Latency: JACK runs 256 frames at 48 kHz (5.3 ms a period), so input → effects → speakers is about 11–16 ms: playable for monitoring a voice or a guitar. (The period could go to 128 if needed, at more CPU.)

    The design: an input chain of jalv effects (ravving's JalvPlugin, wired by JackWiring like DRIVE and the master inserts): capture → chain → monitor (to the master, with its own level) and → the recorder. A take records the wet sound (what you hear), plus optionally the dry input next to it, so the effect can be changed afterwards.

    "Like Tame Impala": Kevin Parker's vocal sound is a known recipe, all on the device: heavy compression (Calf Compressor) → a little saturation (Calf Saturator) → doubling / swirl (Calf Multi Chorus, Phaser or Flanger; the Rotary Speaker for the Leslie wobble) → tape echo (Calf Vintage Delay, slapback + long tail) → a big plate (Dragonfly Plate). Other presets on the same chain: FUZZ VOICE (a guitarix fuzz), ROBOT (Calf Vocoder / TAL Vocoder), TELEPHONE (band-pass), OCTAVE (pitch shift), and for the guitar: AMP (SwankyAmp → guitarix UltraCab → delay → plate). Each preset is data (like kits.json: plugins, fixed controls, and 3–6 knobs for the device knobs: AMOUNT, WOBBLE, ECHO, SPACE…).

    Plan, in phases

    1. Playback (done): a SamplerMachine (a Machine, track 6, "sample-trig"): 4 banks × 8 slots of ClipAudioSources, each bank with its own pattern (the step grid, a row per slot, reusing StepGrid); trim, PITCH, REVERSE, choke; a sample browser (ChoicePopup over /zynthian/zynthian-my-data/samples and Zynthbox's sample library); LIVE pads 1–8; all in the session and projects. Verify on the device: choke through exclusivityGroup, layering, live triggering, CPU with 32 loaded clips.
    2. Recording (done: guitar tested on jack 4; the monitor runs through its own track with a LEVEL, ready for the chain): input mode (MIC / GUITAR / LINE), gain and meter; ● on a slot records a take (count-in on the transport, or free while stopped), processed (DC, compression, normalise, trim to the last burst) in a worker thread, then loaded into the slot.
    3. Live FX (built): the input chain with presets (TAME, FUZZ VOICE, ROBOT, TELEPHONE, OCTAVE, AMP), monitor on/off, record wet (+ dry).
    4. Polish: loudness matching (BS.1770), LAYER, the machine knobs (CUTOFF, BIT CRUSHER on the track lane), and later AUTOTUNE (pitch detection + correction: the heaviest part; a separate study).

    Decisions (taken 2026-10-05)

    • Banks: 4 × 8 slots, as easyrave (a bank fits SketchpadTrack's 10 sample slots).
    • Takes go to /zynthian/zynthian-my-data/samples/my-samples/ravving/, which the browser lists.
    • Record the effect's sound (wet); the clean input next to it is a later option.
    • TAME is the first FX preset.

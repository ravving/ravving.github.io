    The designs / docs/recorder-plan.md

    The RECORDER

    Recording the input freely, as played: the page's design.

    The user's idea (2026-10-09): a full-screen page like the music player for recording the mic, a guitar or a line freely, with monitoring; the recordings kept where the samplers find them; the sampler's wave tools and the live effects reused; for the guitar, the pedals the image has, and a TUNER (automatic: string after string, each one passed on once it is in tune; manual: the string picked by hand; tunings for guitar, bass and ukulele).

    Pieces

    Backend

    • PitchDetector (src/backend/pitchdetector.*): plain C++, no Qt objects. YIN (de Cheveigné & Kawahara 2002: the cumulative mean normalised difference, the first dip under a threshold, parabolic interpolation) on a mono block, decimated to half rate first. Laptop-tested (tests/tst_pitchdetector.cpp: sines and plucked-string-like tones from 30 Hz to 1.3 kHz, noise, silence).
    • Tuner (src/backend/tuner.*, published as studio.input.tuner): ravving's own JACK client ("ravving-tuner", one input) reading the DRY input jack in use (before the effects: a fuzz would hide the pitch). The audio thread only copies into a lock-free ring; the detection runs on the GUI thread 20 times a second, and only while the tuner is shown (active: the client is activated then and deactivated after, so it costs the graph nothing otherwise).
    • Tunings are data (data/tunings.json): name, instrument, the open strings as MIDI notes.
    • reference: A4 in Hz (430–450, 440 by default).
    • AUTO: the strings in order, low to high; a string held within ±3 cents for 0.8 s counts as tuned and the next untuned one is up; after the last, ALL TUNED. A note clearly nearer another string is named ("that is the A string").
    • MANUAL: the string tapped is the target, and stays.
    • Out: frequency, the nearest note, cents off the target, in tune, each string's tuned flag, how far the hold has gone (for the ring).
    • InputRecorder: a take for the RECORDER is kept as played (no compression, no trim: the sampler's processing is for one-shot takes), written to the library's live recordings folder (Paths::liveRecordings()), and said with recordingReady(file); the sampler's takes keep going as now.
    • LiveRecordings (the list): the files in that folder, newest first, with length; rename, delete, TRIM / NORMALISE through AudioFile::writeWindow (already there).
    • Guitar pedals: data/input-fx.json presets marked "modes": ["guitar"] built from the guitarix LV2s on milo (fuzz, overdrive, tube drive, amp + cab) and the Calf modulation; the INPUT popup and the RECORDER list the presets for the mode in use.

    Page (qml/pages/RecorderPage.qml; Session.recorderView, opened from MENU)

    • Top bar: RECORDER, the input tabs MIC · GUITAR · LINE (input.mode), ✕.
    • Left: the input (GAIN, a long meter, the jack lights, MONITOR and its LEVEL), ● REC / ■ with the time and a level trace of the take as it goes, and the EFFECTS for the mode (the pedals on GUITAR) with their knobs.
    • GUITAR: the TUNER in the middle (the needle and cents, the note, the strings as buttons lit as they pass, AUTO / MANUAL, the TUNING picker, A4).
    • Right: the RECORDINGS (newest first); the one picked shows on SampleScreen with its trim, ▶ preview (studio.previewSample), TRIM / NORMALISE, CHOP (WaveEditorPopup) onto SAMPLE KING's bank or the PADS, TO SAMPLE KING / TO PADS (one slot / pad), RENAME, DELETE (double tap).
    • Hardware: the input knobs as in INPUT (knob 1 mode, 2 monitor level, 3 gain, big knob gain), RECORD / SELECT records, ▲ ▼ the recordings, BACK leaves.

    Phases

    1. DONE PitchDetector + its test (42 cases; 0.74 ms a read on milo over the guitar range, 1.4 ms down to 28 Hz); Tuner; tunings.json.
    2. DONE RecorderPage: input, record as played, recordings list, preview (Studio's preview playhead), the tuner on GUITAR; KEEP TAKES IN: SAMPLES or TRACKS (the user, 2026-10-09).
    3. DONE Recordings into the samplers (slot, pad, CHOP), TRIM / NORMALISE, MOVE, rename, delete.
    4. DONE Guitar pedal presets (OVERDRIVE, FUZZ, TUBE, WAH, HOT AMP: guitarix, ports from lv2info on milo), the presets filtered by mode (modes in input-fx.json); each chain starts with no error and no xrun. Their levels are a first pass: to set by ear with a guitar.
    5. Quality pass: static analysis, audio impact (idle = no frames, the tuner's client off when hidden), xruns while recording with the pedals, a screenshot tour; the tuner and a take with a guitar plugged in (the user). Shared base types made on the way: InputSetup and InputEffectsRow (INPUT and the RECORDER), ConfirmButton (to move UsbPopup's EJECT / FORMAT, SongPage's REMOVE onto).

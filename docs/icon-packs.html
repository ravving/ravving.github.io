    Make an icon pack

    Your own drawings for every icon ravving shows: the names and where each one shows, the drawing rules, a tool to build and check a pack, and how to share it.

    An icon pack redraws the icons ravving shows: the transport, the arrows in hints, the settings, the pages. It is one JSON file. Drop it on the device and it shows up in SETTINGS → LOOK → ICONS by its name, beside CANDY, BLOCK and HAIRLINE, with no restart.

    This page is all you need to make one, with or without ravving's source. It lists every icon and where it shows, the drawing rules, and a tool that builds a pack from your drawings and checks it. Then it shows how to put the pack on a MIKO and share it.

    Downloads

    • make-pack.py: the tool. Python 3, nothing to install.
    • The built-in sets as packs to start from: candy.json (16-cell grid), block.json (8 cells) and hairline.json (12 cells).

    How ravving draws an icon

    Every icon is a 1-bit pixel drawing: one shape, filled, on a square grid of cells. Its colour comes from what it sits on: a button's ink, a hint's colour, a lit key's. So a pack has no colours of its own.

    It is drawn at the largest whole scale that fits the space and centred, so a cell is always a whole number of pixels and never blurs. Icons show at 16 pixels in buttons, hints and lists, at 24 in toolbars and larger on a few screens.

    A 12-cell icon at 16 pixels is drawn at its own size with a 2-pixel margin; at 24 pixels, at twice its size.

    An icon a pack leaves out is drawn from CANDY, the set that has them all. A pack can be small: redraw only the transport, and the rest stays as it was.

    The file

    {
    "ravving": "preset",
    "type": "icons",
    "pack": {
        "name": "STENCIL",
        "about": "cut-out shapes with a gap in every outline",
        "author": "your name",
        "grid": 12,
        "icons": {
            "play": "M3 2h1v1h1v1h1v1h1v1h-1v1h-1v1h-1v1h-1z",
            "stop": "M2 2h8v8h-8z",
            "...": "one entry per icon"
        }
    }
}
    • "ravving": "preset" and "type": "icons" are required, or the file is ignored.
    • name is the button in ICONS (capitals read best); about is the line under it.
    • grid is the side of the square, in cells: a whole number from 4 to 16. Every icon of a pack shares it. 8, 12 and 16 fit the sizes icons show at best.
    • icons maps an icon's name (the tables below) to its shape: an SVG path in grid cells.
    • The file name, without .json, is the pack's key: lowercase letters, digits and dashes (stencil.json). The built-in sets' names (candy, block, hairline) are taken. A file named otherwise is not offered: rename it.

    The shape

    A shape is the d of an SVG path, filled with the non-zero rule. ravving draws straight lines only: M, L, H, V and Z, in capitals (absolute) or small letters (relative). A curve, an arc or a name ravving has no icon for is left out, and the checker says so.

    Keep every point on whole cells, inside the grid. A run of cells is easiest written as one rectangle per row: M2 3h4v1h-4z fills four cells of the fourth row, from the third column. The tool writes them that way from a drawing.

    The icons

    Every name, and where it shows. ravving's own hints use some as marks in text: "▲ ▼ pick · SELECT opens" draws caret-up and caret-down in the words' colour.

    Arrows, carets and marks

    Name Where it shows
    chevron-left, chevron-right back and forward, a list's previous and next page
    caret-up, caret-down, caret-left, caret-right the device's ▲ ▼ ◀ ▶ keys in hints; caret-down is also a drop-down button's caret, caret-right the ▸ mark
    dropdown the ▾ mark of a button that opens a list
    arrow-up, arrow-down, arrow-left, arrow-right ↑ ↓ ← → in hints, a step to the next screen
    key-star the device's ✱ key in hints
    note, note-on a note (♪), a note that sounds (♩)

    The carets are the device's keys: keep the four the same shape, turned.

    Draw them

    • Read at 16 pixels. That is the size most icons show at. Look at every one there before anything else; a detail that needs 48 pixels is noise.
    • One weight. Pick a line width (one cell, two cells, solid) and keep it in every icon, so the pack reads as one family.
    • Leave a margin. Icons sit beside text and inside buttons. A one-cell margin on every side keeps them from touching the edge. Centre the shape; an odd-sized shape on an even grid sits half a cell off, so pick the grid for your shapes.
    • Pairs stay pairs. undo and redo, lock and unlock, the carets, the arrows and the chevrons are mirrors or turns of each other. Draw one, then flip it.
    • Shapes, not letters. The icons show in Spanish and Japanese too; a letter only reads in one language.
    • No holes by accident. A shape is filled with the non-zero rule: a hole needs its outline drawn the other way round. From a pixel drawing, the tool gets this right for you.

    Build and check

    Draw each icon as its own file, named after it: play.svg or play.png, in one folder.

    • SVG, from any vector editor: a square viewBox="0 0 12 12" (your grid), <path> and <rect> elements in straight lines, no transforms. Snap to a 1-unit grid and convert shapes to paths before saving.
    • PNG, from any pixel editor: square, one pixel a cell (12 × 12 for a 12-cell grid). Every pixel more than half opaque is ink; in a picture without transparency, dark pixels are.
    python3 make-pack.py start stencil --from block.json   # a folder with names.txt and BLOCK's icons
# draw, replace, delete what you don't redraw
python3 make-pack.py build stencil --name STENCIL --about "cut-out shapes" --author "you"
python3 make-pack.py check stencil.json
python3 make-pack.py sheet stencil.json -o stencil.html

    build writes stencil.json and says what it left out and why. check prints ok or each problem, and exits 1 on one.

    sheet writes a page of every icon at 16, 24 and 48 pixels on a dark and a light background: open it in a browser and compare the icons side by side. unpack PACK.json FOLDER turns any pack back into SVG files.

    Put it on a MIKO

    1. From a USB stick: copy the file into ravving/presets/icons/ on the stick. On the MIKO, MENU → the stick's tile opens the USB page; it copies presets both ways, icon packs among them.
    2. Over the network (developers): copy it to /zynthian/zynthian-my-data/ravving/icons/ on the device, for example with scp stencil.json root@<device>:/zynthian/zynthian-my-data/ravving/icons/. Write the file in one go (copy to another name, then rename), so ravving never reads it half written.
    3. SETTINGS → LOOK → ICONS: the pack is there by its name. Tap it: every icon changes at once, and the pick stays after a restart.

    While the pack is picked, copying a new version of the file over it redraws the icons on screen. So you can keep the device on and copy after every change. Delete the file and the icons go back to CANDY.

    Share it

    Share the file: a friend copies it the same way. Packs in GET MORE (SETTINGS → LOOK → More icons) come from ravving's catalog. To offer yours there, hand over the file, the checker's output and the sheet.

    Checklist for a new pack

    1. Pick a grid (8, 12 or 16), a line weight and a name.
    2. Draw the transport and the carets first: they show the most.
    3. Draw the rest, or leave out what CANDY already draws well enough for your pack.
    4. Run check until it prints ok.
    5. Open the sheet and look at every icon at 16 pixels, on dark and light.
    6. Put it on a MIKO and look at a page of each kind: an instrument page, SETTINGS, a dialog with hints, the SONG page and the music player.

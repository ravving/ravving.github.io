    Architecture

    The layers, the hardware input flow and the focus model, every backend class and QML component.

    Layers

     ┌──────────────── QML (qml/: the Ravving module, compiled in) ────────┐
 │ Main.qml: RaveHeader + StackLayout of the five pages + MENU drawer   │
 │ pages/:   DrumsPage ChordsPage BassPage LeadPage SamplerPage         │
 │ components/: the shared parts every page is built from               │
 └───────────────▲──────────────────────────────▲──────────────────────┘
                 │ context properties           │ Zynthbox QQC style (SVG theme)
 ┌───────────────┴──────── C++ app (src/) ──────┴──────────────────────┐
 │ Ravving         page state, hardware → HardwareEvent   "ravving"    │
 │ Hardware        the `Hardware.on…` attached property  import Ravving│
 │ StyleHost       what the Zynthbox style needs          "zynqtgui"   │
 │ ZynthboxBridge  loads libzyncoder + libzynthbox        "zynthbox"   │
 │ HardwareSwitches  polls the buttons → MidiRouter's CUIA queue        │
 │ HardwareKnobs   polls the 4 knobs (turns / pot positions)            │
 │ UnixSignals     SIGTERM → LEDs off, then _exit (as zynthbox-qml)     │
 └───────────────▲─────────────────────────────────────────────────────┘
                 │ dlopen + meta-object calls (headers are not installed yet)
 ┌───────────────┴──────────── libraries ──────────────────────────────┐
 │ libzynthbox (sequencer, sampler, mixer, MIDI router, engines)        │
 │ libzyncoder (buttons, knobs) · qml-style-zynthbox · KF6 Kirigami     │
 └─────────────────────────────────────────────────────────────────────┘

    Rule: ravving runs no Python. When it needs something zynthbox-qml does in Python, that piece is ported to C++ under src/, and the class doc names the Python it came from.

    Input flow: the Hardware attached property

    The device's keys and knobs reach QML the way the keyboard does through Keys: as events delivered to the item with active focus, bubbling to its parents until a handler accepts them.

    device button ─► HardwareSwitches (zyncoder poll, 20 ms)
                   └► MidiRouter.enqueueCuiaCommand("SWITCH_STEP3_RELEASED")
MIDI-mapped CUIA ─► MidiRouter ─► cuiaEvent ─► ZynthboxBridge ─► Ravving::handleCuia ─┐
device knob ─► HardwareKnobs (zynpot poll) ─► Ravving::handleKnobTurn / handleKnobMove ─┤
keyboard (dev) ─► Main.qml Shortcuts ─► ravving.simulateCuia / simulateKnob ────────────┤
                                                                                         ▼
                        HardwareEvent ─► Hardware::dispatch(window): activeFocusItem,
                                          then each parent, until one accepts it

    import Ravving
FocusScope {
    Hardware.onKnob1Up: event => level += event.delta        // knob 1 clockwise
    Hardware.onBigKnobDown: event => select(index - 1)
    Hardware.onKnob2Moved: event => cutoff = event.value     // Z2_V5B fixed pot, 0..1
    Hardware.onStepPressed: event => grid.toggle(event.index)
    Hardware.onUpPressed: event => { if (atTop) event.accepted = false }  // bubble on
}

    Signals: knob1Up/Down … knob3Up/Down, bigKnobUp/Down, knob1Moved … knob3Moved, generic knobTurned / knobMoved, up/down/left/right/select/back/menu/play/stop/record/metronome Pressed, stepPressed (index 0–15), numberPressed (index 0–4), and pressed for anything else. As with Keys, the specific signal goes first and the generic one gets whatever is still not accepted. A handler that runs accepts the event unless it sets event.accepted = false.

    Focus model: - The open page (a RavePage, i.e. a FocusScope) has the focus. ▲ at a page's top edge is left unaccepted, bubbles to Main.qml, and focuses the header's first group. - In the header, ◀ ▶ move between the KnobGroups and ▼ / BACK return to the page. Step keys always go to the page. A number key nobody handles still switches the page (C++ fallback). - A KnobGroup (FocusScope) hands its targets to the knobs: knob n → targets[n], the big knob → targets[3] or fine steps on targets[0]. It can also hold navItems, which its navKnob (the big knob by default; knob 1 for INSTRUMENTS) steps through and SELECT activates. Targets show a KnobBadge (a tiny knob icon: the knob number, value arc, pulsing while a Z2_V5B pot waits for pick-up). - Inside a page the big knob is always the volume of the machine on screen (RavePage.module, MachineModule.nudgeLevel()); the fader wears the big-knob badge while it is. Groups in a page (ParamCard, the machine strip) set ownsBigKnob: false so it passes through to the page. Popups and the header, outside the page, keep using it. - A machine's strip (role, PAN knob, VOL RaveFader) is a KnobGroup: tap it and knob 1 pans, knob 2 sets the level; BACK or a tap in the grid give the knobs back to the rows (StepGrid.knobsActive is off while the strip has them). - ▲ ▼ walk one vertical order per machine, owned by MachineModule: header → strip → SOUND MODIFIERS cards (only while open) → the editor → SOUND EFFECTS cards (only while open). The sections move the focus themselves (ParamCardRow.released(dy), coming back to the card last used with enter()); a page calls focusUp() / focusDown() when its editor has no further to go (the drums: past the top row / the ACC row; the bass roll: past its top / bottom note row). focusUp() returns false from the strip, so ▲ bubbles to the header; ▼ from the header lands on the page's focusTop() (the strip). - RECORD on an instrument page is that machine's take (the strip's ● shows ● / count-in beat / … / ■); RECORD with the header focused, or ALT + RECORD anywhere, is the global recording (the header's ●, red RECORD LED). - The metronome is libzynthbox's (SyncTimer audibleMetronome) with zynthbox-qml's tick/tock wavs: ZynthboxBridge::setMetronomeSounds() builds the two ClipAudioSources through the exported constructor (no meta-object factory exists) and SamplerSynth's global-sketch1 outputs are wired to the master. - An external MIDI controller plays the machine on screen (on every page; LIVE, which may be left on another machine, is the step keys' only: 2026-10-09) through the same path as the step keys, so REC records it: GM drum notes 35–59 by role (DrumKit::roleForGmNote), any other note cycling through the rows from C2, velocity ≥ 100 an accent. Plugging one in or out shows a Toast (easyrave's dark pill, bottom centre). Debug: QT_LOGGING_RULES="ravving.midi.debug=true". - The key lights (Main.qml's ledColors): ▲ ▼ SELECT BACK ALT MENU always light in a soft white (navigationLight; ALT white while held, MENU while the menu is open); ◀ ▶ light while they switch something on the open page (RavePage.sideKeysLit: the CHORDS views with the editor focused, the drum machines, the sampler banks); PLAY dim green when stopped, bright while playing; STOP dim when stopped, lit while playing; RECORD dim red when ready, red while recording (global or a sampler take), a machine's colour during its take. - ALT + ◀ / ▶ undo and redo the pattern of the machine on screen (the toolbar's ↶ ↷). - ALT + ▲ gives the focus to the app header at once, from wherever it is (a page's rows, a section's cards, the strip): Ravving.headerRequested, raised in C++ before any dispatch. - ALT + 1 opens the SONG page from anywhere, and again goes back to the page (Ravving.songRequested, raised in C++ before any dispatch, its press swallowed too). - The header's INSTRUMENTS chips light the machine on screen only: none while the MIXER, the SONG page, the music player or the RECORDER covers the pages (Session.pageCovered). - AUTO: the header's AUTO arms recording (Studio.recordAutomation): while playing, a SOUND MODIFIERS or SOUND EFFECTS knob turned is written into its machine's pattern at the step playing (Machine automation lanes, step → value, undoable, saved); the toolbar's AUTO plays them back (lit, "•" while there are some; a long press clears them). - SOUND EFFECTS cards (open): SELECT switches the focused card's effect on or off, BACK closes the section and the focus goes back to the editor above (ParamCardRow.selectAndBack). Closed, ▼ past the editor lands on the bar (FxChain.focusBar()): ◀ ▶ ring the chips, SELECT switches the ringed effect, ▼ opens the section on its card, ▲ / BACK go back up. A tap on the ▸ SOUND EFFECTS heading opens it on the effect last touched (the bar has no OPEN button since 2026-10-12: the heading is the one way in by touch). - Dialogs (RavePopup: ChoicePopup, InputPopup), drop-down lists and the menu darken the page behind them (ModalDim); a dialog takes the keys while open and gives the focus back. Dialogs wear easyrave's keyboard-shortcuts card (gradient #1e1c24 → #131118, hairline border, radius 16, DialogHeader: spaced title, hint, ✕); the menu drawer is easyrave's settings panel (gradient #211f28 → #16141c, hairline-split sections under small captions, flat wells that light yellow, #f0c832). - MENU opens the control center (ControlCenter in the drawer): MIXER, Wi-Fi, Bluetooth, MIDI, SYSTEM cards, the power row (REBOOT and POWER OFF need a second press within 3 s), OUTPUT and BRIGHTNESS sliders on knobs 2 and 1; ◀ ▶ walk the actions, SELECT runs one. - ✱ (starPressed) opens and closes the MIXER (MixerPage, the StackLayout's sixth view, Main.mixerOpen); a number key leaves it for that page. In it ◀ ▶ or step keys 1–9 pick a strip, knob 1 is its level, knob 2 its pan, the big knob fine level, SELECT mutes, ALT + SELECT solos, BACK or ✱ go back; the step LEDs show the strips (muted dim, picked white). - MODE switches LIVE on the open page's instrument (from anywhere; the MODE LED shows it). ALT is a modifier held in C++ (Ravving.altHeld): ALT + big knob is the master volume wherever the focus is (masterTurned, never dispatched), badged on the MASTER dial, and ALT + knobs 1–3 go straight to Ravving.altKnobTarget (the header's FX SENDS: PHASER, ECHO, HEAVY), a KnobGroup borrowed while ALT is held (badges, frame, pick-up). - A machine's ❚❚ pauses its written pattern (DrumMachine.paused → Sketchpad.setTrackPaused: its clip stops in PlayfieldManager and is left out of the launch at play; resuming rejoins on the next bar); it stays playable live. - LIVE (one machine at a time, Session.liveMachine) turns the step keys into pads (Hardware.onStepDown on the press, onStepPressed on the release): on the drums keys 1–8 play the rows and key 9 held makes accents; with REC on while playing a hit is written at the nearest step (Machine::recordLive, timed against the measured step length), in STEP entry while stopped at the cursor (writeAtCursor). With the toolbar's Q off (Machine.quantise) the hit keeps its distance from that step as the subnote's delay (SyncTimer ticks, negative when early), so it plays back as played; the machine keeps these offsets itself (timing in its state) and puts them back whenever its model rewrites the pattern (syncTiming). The LEDs show the pads (rows in the machine's colour, key 9 red, white while held) and drop the playhead (RavePage.stepKeysArePads). libzynthbox's own live recorder is not used: it only hears controller ports, and pads sent through SyncTimer arrive as sequencer traffic. - The toolbar's ⟲ (Machine.loopBar) plays only the bar on screen: the pattern's playback window moves to it (bankOffset = that bar, patternLength = one bar) while bars keeps the real length, and paging with ‹ › moves the loop. Not saved; attach and restore put the window back.

    Backend (src/backend/)

    The drums play through libzynthbox exactly the way zynthbox-qml's sketchpad does, with ravving's C++ objects standing in for the Python ones libzynthbox talks to:

    Class Role Stands in for / ports
    Studio backend root (studio in QML): builds the machines from data/kits.json, transport (play/stop, tempo, swing, step), saves the sequence after edits; a preview clock on a desktop; the sampler's browser (sampleFiles(): kits.json sampleFolders, folders labelled short) and hold-to-hear previews (previewSample() / stopPreview(): a one-shot clip on SamplerSynth's global lane) sketchpad song + transport glue
    Machine the base of every machine: track (level, pan, effects, mute, ❚❚, kick cuts), pattern (bars, view bar following the playing bar while playing: follow, off when a bar is picked mid-play, back on when stopped; playhead, STEP cursor), presets, LIVE play/record, UNDO / REDO of the pattern (canUndo, undo(), canRedo, redo(): every edited whose content differs is a step back, 50 deep, changes within 0.5 s of the last joining its step (a knob turned, a handle dragged); the mix, sound and effects are left out, and so are a subclass's viewKeys() such as the sampler's bank; beginEditGroup()/endEditGroup() make a take one step; a project open starts it afresh); subclasses give steps, sound and velocities; SECTIONS: sectionContent() (the pattern part less soundState()'s keys and the viewKeys(), plus ❚❚ and ONCE) and applySectionContent() (laid over the machine's own by withSection(), the history started over; an empty map empties the pattern), sectionBars() / sectionSounds(); the samplers keep their banks' hits, not their samples (SamplerBanks) Its own length (bars, m_bars) is kept apart from what its clip plays: applyPlayLength() is the one place that sets the clip's patternLength and bankOffset, from playedBars(): one bar under ⟲ (the bar on screen), the section's span under ONCE (once, setSpan() from the studio; the bars past its own emptied by clearRest()), else its own; while it rests the playhead hides and a live hit is not written. new
    MonoMachine a mono line (one note per step) with ACCENT and SLIDE (the note lasts 1.5 steps and a legato engine glides into the next): page 3's AC 303 (bass, DISTRHO Nekobi: accent velocity 127 vs 80, Nekobi accents above 90) and page 4's THERE LEAD (lead, Calf Monosynth, legato + portamento); base note and velocities from kits.json; presets in scale degrees (bass-presets.json, lead-presets.json), RANDOM, octave; follows the header's key: a ROOT or SCALE change snaps every note to the nearest note of the new key (upwards on a tie, as easyrave's snapAll), and the line's key is saved with it easyrave's AC 303 and THERE LEAD
    ChordMachine page 2's POLY-6 on TAL NoiseMaker (6 voices, Juno chorus); a custom voicing is scale degrees, or chromatic (semitones from the chord base, chart letter c) when a note is outside the key, so a chart can carry a C7 in E♭ major; setStepNotes(step, "48,52,55,58") for scripts; live keys below 1000 are chord degrees, from 1000 on single scale degrees (noteKey, noteKeyForNote, noteOfKey: the NOTES tab's LIVE, written one note into the step's voicing by a take or STEP entry): each step holds a voicing, a diatonic chord (a degree stacked in thirds from the scale, triad or seventh per degree by the chord set: Classic, Triads, Sevenths) or a custom set of scale degrees (built in NOTES); a run of one voicing is one held chord; everything is in scale degrees, so a key, set or octave change revoices it all. Three views: CHORDS (setChord), NOTES (noteSets, toggleNote), SLOTS (four chordSlots of 1/2/4/8 bars, armedSlot, assignSlot, cycleSlotBars, clearSlot: editing one rebuilds the steps in order). LIVE keys and the chord keys play whole chords, a keyboard note plays its degree's chord; presets chord-presets.json ("1111666633337777", "x" + VOICINGS for custom) easyrave's POLY-6
    SoundPresets an LV2 plugin's factory presets read from its bundle's presets.ttl (name, category from TAL's prefix, port values); a machine's kits.json soundPresets {file, keep} gives it soundPresets / soundPreset / loadSoundPreset(): the ports are set (but keep), the SOUND MODIFIERS take the values (adopt()), the name is saved, and an engine restart sends the sound again before the knobs new
    SoundControls a machine's SOUND MODIFIERS driving its engine's own ports, built from the machine's sound in kits.json (owned by Machine): cards of knobs, 0..1 mapped onto min..max linearly or with "curve": "log"; a knob with choices is a switch (snaps to i / (n − 1), ParamCard draws it as a WaveCycler) whose choices can each set several ports (TAL's JUNO wave: waveform + pulse width + levels). Bass: WAVE · FILTER (CUTOFF RESO ENV MOD) · VOICE (DECAY ACCENT TUNE); chords: FILTER (CUTOFF RESO LFO) · SHAPE (ATTACK LENGTH GLIDE) · TONE (WAVE SAW/JUNO/SQR/TRI, SPREAD, CHORUS OFF/I/II); lead: WAVE (SAW SQR SIN TRI) · FILTER (CUTOFF RESO ENV) · VOICE (GLIDE LENGTH). Machine::setExpression() plays kits.json expressions live (the ribbon's vibrato = Calf lfo2pitch) new
    JalvPlugin, JalvEngine one LV2 plugin in jalv (effects, and instruments with MIDI in); JalvEngine makes an instrument a machine's SoundEngine (a mono output feeds both sides) zynthian_engine_jalv.py
    DrumMachine one drum machine: kit rows, steps as subnotes of its track's PatternModel, accents, presets, per-row level/mute/solo (as velocities), level (track gain), pan (track passthrough), mute, audition, kit switching and reset new
    TakeRecorder a machine's REC (studio.take): a fresh take of what is played LIVE, counted in by the transport's first bar (stopped) or punched in at the loop's restart (playing), overdubbing loop after loop; holds the metronome on for the take easyrave's per-machine ● REC
    MidiInput external controllers (studio.midiIn; devices: the connected ones' names): notes from MidiRouter's hardware port (raw controller notes parked on unused track 9; every device's channels reset to the current track; bridge duplicates dropped), plug-in/out notices zynthbox-qml's MIDI controller handling (subset)
    VideoRecorder LIVE REC (video, docs/video.md): a video of the screen (x11grab) or a USB camera (v4l2) with the master's sound, or (mode "audio") the sound alone as a 24-bit WAV among the exports (finished with tags through Exporter::finishRecording), encoded by ffmpeg (libx264, two threads, nice 10; three measured tiers) into videos/<project> - <date>.mp4; the sound comes from AudioTap, the sync from the wall clock on both inputs (-copyts, -itsoffset = the tap's first-sample moment), the file goes to Matroska first and is remuxed once to MP4 with its head cut to the first frame; states off / ready / countdown / starting / recording / saving, takesKey gives it RECORD and STOP while VIDEO is on (Ravving::handleCuia); VIDEO SAVED sends it on (ComputerLink, a USB stick) new
    AudioTap ravving's JACK client ravving-video (stereo in): the master's last outputs copied on the audio thread into a 2^20-frame ring (21 s), drained by a plain thread into a named pipe ffmpeg reads as raw float; the first sample's CLOCK_REALTIME from jack_get_cycle_times; frames the ring could not hold are counted, never lost quietly; the mic inputs mixed in, plain or as a voice over (setVoiceOver(duckDb, liftDb): a 120 Hz high-pass and a +4 dB shelf from 3 kHz on the mic, its envelope followed, the master ducked while it speaks, the sum through a peak limiter at −1 dBFS, never clipped) new
    FileBrowser the FILES browser (files, FilesPopup): the library by kind ({key, label, about, usbKind, count}; projects through Projects, presets and templates through PresetExchange, the rest by folder and suffix from filesuffixes.h, shared with UsbLibrary), entries(kind) newest first, presetFile(id) to send a preset as one JSON file, remove(entry) through the owner (Projects, the preset library, the machine, Templates) or the file new
    Computers the user's computers over SSH (computers, SETTINGS · COMPUTERS): any number of ComputerLinks, each in its own settings group computers/<id> (the single computer of before migrated into c1), add(host, user, password) (the same user@host set up again, not added twice), send(id, files), byId, current (the last added or set up), busy / phase, the links' sent / notify / setupFinished passed on with the id new

    MixRecorder the global recording (studio.mix): the master (GlobalPlayback) to recordings/ravving-<date>.wav through AudioLevels (refused while a sampler take records: AudioLevels runs one recording at a time); the music player lists these under "Recordings" easyrave's top-bar RECORD
    PadSamplerMachine page 5's PAD SAMPLER (studio.machines.pads, kind "pads", docs/mpc-sampler-plan.md): 4 banks × 16 pads, each loaded pad one ClipAudioSource set up from the pad's params[tab][knob] (TRIM start / end / loop point, MIX pan, AMP ENV attack and decay / release, TUNE semi + fine, PLAY mono / mute group as exclusivity groups) and flags (NOTE ON = NonLooping, LOOP = Looping from the loop point, REVERSE = a reversed copy, MUTE; 16 LEVELS kept); pads 1–10 on track 7, 11–16 on a second track (kits.json secondTrack 8) whose pattern the machine mirrors (hits, length, loop, swing, mute) and whose live notes go out on it, both tracks' sample outputs wired into track 7's lane (JackWiring::setSampleOutputs(track, samples, laneTrack)); level as velocity; FILTER = the clip's equaliser bands (one, two for the 4-pole types, cutoff and Q from the knobs); the kit's knobs (PadKitControls, the SOUND MODIFIERS: KIT volume / semi / fine, 16 LEVELS type and switch); 16 LEVELS: the selected pad becomes the source, every pad plays it by velocity ramp or on sixteen level slices (notes 64–79, transposed by root note per TUNE semitones or the header's SCALE from pad 4), the hits meanwhile are the bank's level hits; audition = one pass; latch = the note held with the slice looping, unlatched after a short delay so the note-off is not ignored; PAD FX held on the pad played last (heldFx, fxPad): ECHO = the track's echo throw, TAPE STOP / SCRATCH = sweeps of the clip's speedRatio (a QVariantAnimation), STUTTER = a sixteenth-of-the-tempo retrigger, SKIP / REVERSE = the pad restarted with its start moved on / its reversed copy from the point reached, restored on release; erase pad, halve / double, UNMUTE ALL; presets pads-presets.json ("1"–"16"); playing and playPositions (per pad: whether its clip sounds and where it is in the file, from the clip's isPlaying / position signals) feed the grid's beam and the screen's playhead the MPC Sample
    SamplerMachine page 5's SAMPLE KING (studio.machines.sampler, track 6, "sample-trig"): 4 banks × 8 slots, each slot one ClipAudioSource (made through the bridge's exported constructor) on its track's sample slot i % 5, row i / 5, set up on its root slice: key zone = root note = baseNote + i, one-shot (a retrigger chokes it), PITCH = slice pitch, trim = start/length samples, 8 ms release; REVERSE plays a reversed copy rendered once in a worker (AudioFile::writeReversed, cached by path hash). Steps, accents and row mix as the drums (velocities); presets sampler-presets.json ("1"–"8": x/X). Published to the track as samples (SketchpadTrack::setSamples), its loaded slots' SamplerSynth ports wired into the lane (JackWiring::setSampleOutputs); playing / playPositions per slot as the PAD SAMPLER has easyrave's SAMPLE KING
    InputEffects the live effects on the device input (studio.input.effects): presets from data/input-fx.json (TAME, FUZZ VOICE, ROBOT, TELEPHONE, OCTAVE, AMP; OFF = the plain input), each a chain of jalv plugins (ravving-in-<preset>-<n>, started the first time it is picked and kept running) with fixed controls and three knobs mapped onto ports (linear or log); "bpm" delays follow the studio tempo. InputRecorder wires input → chain → monitor track and → the port recorder (JackWiring::setInputChain, which also makes the recorder connections, retried until a new plugin's ports exist): what is heard is what is recorded new (the recipe in sampler-plan.md)
    AudioFile libsndfile helpers run in workers: info, writeReversed, transients (onsets on the 10 ms peak envelope for the wave editor's THRESHOLD chop), writeWindow (a trim to a new file, normalised to −1 dBFS when asked), processTake (a 12 dB/octave high-pass by mode: MIC 80 Hz, GUITAR 40, LINE 20; a noise gate set 12 dB over the take's own noise floor, up to −30 dB; 3:1 compression 15 dB under the peak; normalise to −1 dBFS; refuse takes under −50 dBFS; the last burst as the trim). On a real mic take it left the pauses at −48 dBFS where the first version (6:1, no gate) brought them up to −39 new
    InputPorts the input card's JACK capture ports found by the card, not a name: pw-dump gives the port whose alias is ":capture_FL/FR" and its serial; its JACK name is ":capture_FL-" when that exists, else the plain one (milo's two "Built-in Audio Stereo" cards swap the suffix between boots) new
    InputRecorder the device input (studio.input): MIC / GUITAR (mono: the jack with the signal, activeJack, followed between takes) / LINE set the ADC's PGA gain and mic bias through amixer (-- before the arguments: negative gains); armed connects the input to AudioLevels' port recorder, whose meter is level; MONITOR runs the input through its own track (kits.json input.track, 9) whose gain is monitorLevel; a take is the port recorder into a raw WAV, processed in a worker into samples/my-samples/ravving/ (takeReady(file, start, length)). Mode, gains and monitor level are the device's (QSettings ravving/input) easyrave's mic takes

    Contracts found the hard way (libzynthbox crashes or stays silent otherwise): - SketchpadTrack.samples must hold ten entries (PatternModel reads sample slots 0–9). - SamplerSynth makes a track's channel_N-sampleM ports only while a clip is registered on that slot: wire exactly the loaded ones, again whenever they change. - AudioLevels starts every recorder set to record: a take turns the master's writer off (setRecordGlobalPlayback(false)), the mix turns the port recorder off. - AudioLevels' own capture meter (captureA/B) reads the speakers under PipeWire (it takes the first system: outputs, the monitor): meter the input through the port recorder. - PipeWire has a second "Built-in Audio Stereo" (the Dummy card): its ports get a number suffix (capture_FL-17167); the plain names are the HiFiBerry's. - PlayGridManager's zlSketchpad must be set before playing (SyncTimer dereferences it). - A pattern only plays while PlayfieldManager has its clip in PlayingState, and stopping resets every clip: the clips are re-launched from Sketchpad::startPlayback(). - Never call Plugin::shutdown(); exit with _exit() (see the exit row below).

    Kits. data/kits.json holds every machine: drumMachines (track, Zynthian channel, engine, default kit and preset) and machines by kind (mono: bass on track 3, lead on track 5; chords: track 4), each with its engine (type, LV2 URI, fixed controls), its sound (SOUND MODIFIERS), presets file, defaultPreset, baseNote and velocities. Studio builds them generically and publishes the non-drum ones as studio.machines.<key>. Also the kit folder (the 40 drum-machine soundfonts in zynthian-data). Grid rows are not written by hand: DrumKit reads them out of the kit (soundfonts are not General MIDI: the 909's clap is on 50, the Linn's on 39). Tapping a machine's nameplate opens ChoicePopup with every kit; DrumMachine::loadKit() moves each hit to the new kit's note for its role (keeping accents), the engine reloads the soundfont (SoundEngine::reconfigure), and the choice is saved in the session (session.json). A double tap on the nameplate goes back to the default kit (resetKit()). A new engine type is one SoundEngine subclass plus a line in SoundEngine::createEngine().

    Presets are factory beats (House, Techno, Electro, Breaks, Hip Hop, Groove, Empty) that replace the pattern. They are drum charts written per role ("KICK": "X...x...", X = an accented hit), so every preset plays on every kit. The toolbar's PRESET button shows the loaded preset (• once edited) and opens a ChoicePopup by genre; SAVE CURRENT AS NEW stores the pattern as "My Beat N" in Paths::presets()/drum-presets.json, and DELETE removes a user preset. The other machines save the same way into their own file, named by the factory file's userName ("My Bassline N", "My Progression N", "My Melody N", "My Pattern N").

    Row mix. Each row's level, mute and solo are kept per role (they survive kit changes) and live in the hits' velocities: level 0.8 → velocity 100, an accent hits ×1.27 harder, and a muted or soloed-out row gets velocity −1, PatternModel's "do not play". Accents are kept by the machine and saved in the session with the row mix, never read back from velocities.

    Pages combine these and hold only page-specific logic: the bassline generator, the bank switching, the chord cursor. Generic controls (buttons, combo boxes, sliders, tabs) come from the Zynthbox Quick Controls style, so they follow the active SVG theme; the dials are ravving's own (DialFace), since the theme's SVG dial breaks up at the small sizes the machines use. easyrave-specific parts (key caps, nameplates, grids) are drawn in QML from each machine's finish in Rave.machines.

    The libzynthbox bridge

    libzynthbox doesn't install headers, and its headers pull in all of JUCE. So for now ZynthboxBridge:

    1. dlopens libzyncoder.so and calls init_zynlib(). libzynthbox needs zyncoder's MIDI router first, the same order as zynthbox-qml.
    2. dlopens libzynthbox.so and resolves three symbols: Plugin::instance(), Plugin::initialize() and Plugin::registerTypes().
    3. Gets the MidiRouter QML singleton and connects to cuiaEvent through the meta-object system.

    Both libraries are opened with RTLD_LOCAL. RTLD_GLOBAL lets libzynthbox's bundled JUCE/tracktion symbols interpose on libraries loaded later, and the app crashes in Kirigami's platform-plugin lookup.

    Next step for the bridge: make libzynthbox install its headers and a CMake config, then replace the bridge with a normal link.

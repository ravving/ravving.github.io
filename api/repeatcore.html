    Detailed Description

    engage() gives an anchor frame and a length: the audio from the anchor plays out live, then repeats every length frames until release(); setLength() changes the length of a running repeat on the same anchor. The input is always kept (HistoryFrames, 2.7 s at 48 kHz); an engagement copies what already played since its anchor into the slice it repeats (at most SliceFrames, 5.4 s).

    Each repetition's head is crossfaded (SeamFrames, 10 ms at 48 kHz, equal power) with what followed the slice when it first played, so the seam never dips to silence; the switch into the repeat eases over SwitchFrames and the release over ReleaseMs (an S-curve), so the repeat gives way to the live sound rather than being cut.

    A repeat engaged on silence (a break in the music: nothing above SoundThreshold since its anchor) waits: the live input passes, and the first sound moves the anchor to the start of the step it lands in (engage()'s stepFrames keep it on the grid), so the music coming back is what repeats, not the break.

    It also passes on only sound: a sample that is not finite, or beyond MaxSample, is passed on as silence. The GUI thread calls engage(), setLength() and release(); the audio thread reads only atomics and the buffers prepare() allocated.

    Member Function Documentation

    RepeatCore::RepeatCore()

    Constructs a core at rest; prepare() must run before process().

    [static] quint32 RepeatCore::clampedLength(double frames)

    Returns frames clamped to what a repeat can hold: 16 frames to SliceFrames.

    void RepeatCore::engage(quint64 anchor, quint32 length, double stepFrames = 0)

    Starts a repeat of length frames from anchor, a frame of the audio clock (in the past or just ahead): what played since it comes from the history, the rest is taken as it plays. stepFrames, a 16th's length, keeps a repeat engaged on silence on the grid when the sound comes (0: it starts where the sound starts). Any thread.

    bool RepeatCore::isIdle() const

    Returns whether the live input passes untouched: nothing engaged and the release over. The audio thread's state (tests read it between cycles).

    bool RepeatCore::isRepeating() const

    Returns whether a repeat is engaged.

    void RepeatCore::prepare(double sampleRate)

    Allocates the history and the slice and sets the release for sampleRate. Call it before the audio thread runs process(), never while it does.

    void RepeatCore::process(const float *inLeft, const float *inRight, float *outLeft, float *outRight, quint32 frames, quint64 startFrame)

    Runs one cycle of frames frames starting at the audio clock's startFrame: inLeft and inRight in, outLeft and outRight out (they may be the same buffers). Audio thread.

    void RepeatCore::release()

    Returns to the live input, over the release. Any thread.

    void RepeatCore::setLength(quint32 length)

    Changes a running repeat's length to length frames, on the same anchor. Any thread.

    [static] quint64 RepeatCore::tickCount(quint64 ringIndex, quint64 nearTicks, quint64 ringSize)

    Returns the tick count nearest to nearTicks whose index in a ring of ringSize is ringIndex: how a position in SyncTimer's step ring (its timerTickForJackPlayhead) is read back as the tick it stands for, given the timer's own count (cumulativeBeat, within a few ticks of it).

    Member Variable Documentation

    const quint64 RepeatCore::HistoryFrames

    This variable holds the input kept, in frames (a power of two, for masking): 2.7 s at 48 kHz.

    const float RepeatCore::MaxSample

    This variable holds the largest sample passed on: anything beyond (or not finite) is garbage, not sound.

    const double RepeatCore::ReleaseMs

    This variable holds the release, in milliseconds: the repeat gives way to the live sound over this long.

    const quint32 RepeatCore::SeamFrames

    This variable holds the seam between two repetitions, in frames: 10 ms at 48 kHz.

    const quint32 RepeatCore::SliceFrames

    This variable holds the longest slice a repeat can hold, in frames: 5.4 s at 48 kHz.

    const float RepeatCore::SoundThreshold

    This variable holds the level (-70 dBFS) above which a sample counts as sound for a repeat engaged on silence.

    const float RepeatCore::SwitchFrames

    This variable holds the eased crossfade into the repeat, in frames: 10 ms at 48 kHz.

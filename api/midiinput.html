    Detailed Description

    libravving's router receives every connected controller. Left alone it would play a controller's raw notes on its current sketchpad track, straight into that track's engine; ravving points that at a track it does not use, so the notes reach no engine and arrive only here (libravving::Router::onControllerMidi).

    A device can also send its channels to tracks of their own, and the library loads saved per-device settings incorrectly (MidiRouterDevice turns each saved track into a bool, so every channel lands on track 1). So every controller's channels are set back to the current track at start and whenever one is plugged in.

    A controller's settings start from the known defaults for its name in data/midi-devices.json (devices: match, a part of the name, and/or usb, the USB id of its sound card ("vendor:product", for a controller whose name many devices share), with label, the name to show it by, and any of the settings below, hits as a note to a slot and controls as a control id to a message), the MIDI standard's otherwise; a controller that says its own pitch bend range (RPN 0, as the MPE specification has an MPE controller do on connecting) sets it. Each controller has settings of its own, kept by its name in the ravving/midi settings: the channel it is heard on (0: all sixteen), a transpose in semitones, a fixed velocity (0: as the device sends it) and a velocity curve (0 as sent, 1 soft, 2 softer: light touches louder, for pads that send most taps under 10), whether its expression is played and the pitch bend range it sends in, the drum keys (a note to a drum row or a pad, learned) and the controls (a note or a CC to one of the device's keys or knobs, learned). learn() takes the next message from a controller as what is learned instead of playing it.

    A learned key presses on a note-on (or a CC at 64 or more) and lets go on its note-off (or the CC under 64); it reaches the app as the device's own key would (cuia()). A learned CC on knob 1 to 3 is a fixed knob at the CC's position (knobMoved()); on the big knob it turns it by the CC's change (knobTurned()), a relative encoder's 1 / 65 (up) and 127 / 63 (down) included.

    A controller's expression (pitch bend, channel pressure, and the control changes no control is learned as: the mod wheel, sustain, an MPE slide's CC 74) goes to the machine played as expression(), from the channel of the note pressed last only: an MPE controller (a Lightpad) plays each note on a channel of its own and bends each, while a machine plays one channel. The bend is scaled from the controller's range to the engines' ±2 semitones, and centred again when the last note is let go.

    A controller seen through two bridges (ALSA's a2j and PipeWire's Midi-Bridge) delivers each message twice; a copy arriving within a few milliseconds is dropped. Enable QT_LOGGING_RULES="ravving.midi.debug=true" to log the messages. GUI thread only.

    Property Documentation

    [read-only] controls : const QVariantList

    This property holds the device's keys and knobs a controller's notes and CCs can be learned as: a list of maps with id (PLAY, STEP1, KNOB1, BIGKNOB…), label, and knob (true for a knob, which a CC drives).

    Access functions:

    QVariantList controls() const

    [read-only] devices : QStringList

    This property holds the connected controllers' names, each once; ALSA's Midi Through and the device's own serial MIDI are left out.

    QStringList devices() const

    [read-only] learning : QString

    what the next controller message is taken as: hit (a drum key), control (a key or a knob), or empty while nothing is learned.

    Member Function Documentation

    [explicit] MidiInput::MidiInput(int *router, const QString &profilesFile = QString(), QObject *parent = nullptr)

    Listens to libravving's router (null on a desktop: no input), and points every connected controller's channels at the current track, with the given parent; profilesFile is the known controllers' defaults (data/midi-devices.json).

    [invokable] void MidiInput::clearControl(const QString &device, const QString &control)

    Forgets what works control from device.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void MidiInput::clearHits(const QString &device)

    Forgets device's drum keys: its notes play the drum rows of their General MIDI drums again.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::cuia(const QString &cuia)

    Emitted when a learned key went down or came up: cuia is the device key's own command (SWITCH_PLAY_PRESSED…).

    [invokable] QString MidiInput::describe(const QString &message) const

    Returns message ("note 1 60", "cc 2 74") as the user reads it: "C4 · CH 1", "CC 74 · CH 2".

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::deviceAdded(const QString &name)

    Emitted when a controller was plugged in, with its readable name.

    [signal] void MidiInput::deviceRemoved(const QString &name)

    Emitted when a controller was unplugged, with its readable name.

    [signal] void MidiInput::expression(int status, int data1, int data2)

    Emitted for a controller's expression while it plays: status is 0xE0 (pitch bend, data1 and data2 its low and high 7 bits, scaled), 0xD0 (pressure, data1) or 0xB0 (control change data1 at data2), with no channel (Machine::sendLive()).

    [invokable] void MidiInput::forget(const QString &device)

    Forgets all of device's settings: it starts again from the known defaults.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::knobMoved(int knob, qreal value)

    Emitted when a learned CC moved knob (0 to 2) to value, 0 to 1.

    [signal] void MidiInput::knobTurned(int knob, int delta)

    Emitted when a learned CC turned knob (3: the big knob) by delta detents.

    [invokable] void MidiInput::learn(const QString &device, const QString &what)

    Takes the next note or CC from device (any controller, when empty) as what is learned (what: hit or control), reported by learned() instead of played; learning goes on until stopLearning().

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::learned(const QString &device, const QString &message, int note)

    Emitted while learning, for the message device sent ("note CH N" or "cc CH N", the channel 1 to 16); note is the note played, -1 for a CC. Nothing is stored: the asker stores it (setHit(), setControl()).

    [invokable] QString MidiInput::noteName(int note) const

    Returns MIDI note's name, "C4" for 60.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::noteOff(int note)

    Emitted when a key note came up on a connected controller (a note-on with velocity 0 included), the note noteOn() gave.

    [signal] void MidiInput::noteOn(int note, int velocity, int slot)

    Emitted when a key note went down on a connected controller, with velocity 1 to 127, after the controller's channel, transpose and velocity settings; slot is the drum row or pad it was learned as, -1 without one.

    void MidiInput::receive(const QString &device, int size, quint8 byte0, quint8 byte1, quint8 byte2)

    Handles the message of size bytes byte0 byte1 byte2 from the controller device: learns it, works the control it is learned as, or plays it.

    [invokable] void MidiInput::setControl(const QString &device, const QString &message, const QString &control)

    Has device's message (from learned()) work control (an id of controls()). A message works one control, and a control is worked by one message.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void MidiInput::setHit(const QString &device, int note, int slot)

    Has device's note play drum row (or pad) slot; a slot under 0 forgets the note. A note plays one slot, and a slot is played by one note.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void MidiInput::setOption(const QString &device, const QString &option, int value)

    Sets device's option to value: channel (1 to 16, 0 all), transpose (semitones, −48 to 48), velocity (1 to 127, 0 as sent), curve (0 as sent, 1 soft, 2 softer), pressure (0 as sent, 1 firm, 2 firmer: light presses send less, for a surface that reaches its top halfway), bendRange (the semitones its full bend is, 1 to 96) or expression (0 off, 1 on).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    void MidiInput::setSoundCardsDir(const QString &dir)

    Reads the sound cards (their names and USB ids, for the known defaults' usb) from dir instead of /proc/asound.

    [invokable] QVariantMap MidiInput::settings(const QString &device) const

    Returns device's settings: channel (0 all), transpose, velocity (0 as sent), curve, pressure, bendRange, expression (a bool), hits (a note, as text, to its drum row or pad) and controls (a control id to its message).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::settingsChanged(const QString &device)

    Emitted when device's settings changed.

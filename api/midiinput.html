    Detailed Description

    libzynthbox's MidiRouter receives every connected controller. Left alone it would play a controller's raw notes on its current sketchpad track, straight into that track's engine; ravving points that at a track it does not use, so the notes reach no engine and arrive only here (MidiRouter::midiMessage, from its hardware input port).

    A device can also send its channels to tracks of their own, and libzynthbox loads saved per-device settings incorrectly (MidiRouterDevice turns each saved track into a bool, so every channel lands on track 1). So every controller's channels are set back to the current track at start and whenever one is plugged in.

    A controller seen through two bridges (ALSA's a2j and PipeWire's Midi-Bridge) delivers each message twice; a copy arriving within a few milliseconds is dropped. Enable QT_LOGGING_RULES="ravving.midi.debug=true" to log the messages. GUI thread only.

    Member Function Documentation

    [explicit] MidiInput::MidiInput(QObject *midiRouter, QObject *parent = nullptr)

    Listens to midiRouter, libzynthbox's MidiRouter (null on a desktop: no input), and points every connected controller's channels at the current track, with the given parent.

    [signal] void MidiInput::deviceAdded(const QString &name)

    Emitted when a controller was plugged in, with its readable name.

    [signal] void MidiInput::deviceRemoved(const QString &name)

    Emitted when a controller was unplugged, with its readable name.

    [signal] void MidiInput::noteOff(int note)

    Emitted when a key note came up on any connected controller (a note-on with velocity 0 included).

    [signal] void MidiInput::noteOn(int note, int velocity)

    Emitted when a key note went down on any connected controller, with velocity 1 to 127.

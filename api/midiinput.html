    Detailed Description

    The messages come from the ConnectionMultiplexer (receive()), each stamped with its controller (a ControllerId: one controller however many connections it has) and already told from its copies over the controller's other connections; the controllers themselves are the ConnectionRegistry's (studio.controllers). Everything here is per controller, by its id, which QML passes as a string.

    A controller's settings are a ControllerSettings, read from and written through the ControllerSettingsStore (its profile's defaults under the user's choices, one writer for everything kept per controller): the channel it is heard on (0: all sixteen), a transpose in semitones, a fixed velocity (0: as the device sends it) and a velocity curve (0 as sent, 1 soft, 2 softer: light touches louder, for pads that send most taps under 10), whether its expression is played and the pitch bend range it sends in, the drum keys (a note to a drum row or a pad, learned) and the controls (a note or a CC to one of the device's keys or knobs, learned). setOption() sets a scalar one by its name (ControllerSettings::Field). A controller that says its own pitch bend range (RPN 0, as the MPE specification has an MPE controller do on connecting) sets it. learn() takes the next message from a controller as what is learned (Midi::LearnTarget) rather than playing it.

    A learned key presses on a note-on (or a CC at 64 or more) and lets go on its note-off (or the CC under 64); it reaches the app as the device's own key would (cuia()). A learned CC (or pitch bend) on knob 1 to 3 is a fixed knob at its position (knobMoved()); on the big knob a CC turns it by its change (knobTurned()), a relative encoder's 1 / 65 (up) and 127 / 63 (down) included. A note, a CC or a pitch bend learned as one of the MIXER controls (a strip's volume, pan, mute, solo, take or pause, the transport's ❚❚, a bar back or on, the previous or the next machine: MixerControl) goes to mixerControl(), for the controller's LearnedMixer.

    A controller can be a control surface (surface: mackie, from its profile or setSurfaceType()), hosted by that driver (ControllerDrivers), which reads its endless knobs' encoding (knobs: sign-magnitude, twos-complement, offset-binary) and its faders' pick-up (pickup) from the same settings.

    A controller's expression (pitch bend, channel pressure, and the control changes no control is learned as: the mod wheel, sustain, an MPE slide's CC 74; never one that sets an engine channel's own state, EngineMidi::isChannelState()) goes to the machine played as expression(), from the channel of the note pressed last only: an MPE controller (a Lightpad) plays each note on a channel of its own and bends each, while a machine plays one channel. The bend is scaled from the controller's range to the engines' ±2 semitones, and centred again when the last note is let go.

    A control surface hosted by its driver (setSurface(): a Mackie Control mixer) hands each of its messages to the driver first; what the driver leaves works its learned keys and knobs only and never plays. GUI thread only.

    Property Documentation

    [read-only] controls : const QVariantList

    This property holds the device's keys and knobs, and the mixer's controls, a controller's notes, CCs and pitch bends can be learned as: a list of maps with id (PLAY, STEP1, KNOB1, BIGKNOB, MIXER1_VOLUME…), label, group (keys, knobs or mixer), knob (true for a knob or a level, which a CC drives), bend (true for one a pitch bend can drive: a fader) and, for the mixer's, strip (0 up, -1 the transport).

    Access functions:

    QVariantList controls() const

    [read-only] learning : Midi::LearnTarget

    what the next controller message is taken as: hit (a drum key), control (a key or a knob), or empty while nothing is learned.

    [invokable] QString MidiInput::describe(const QString &message) const

    Returns message ("note 1 60", "cc 2 74", "bend 3") as the user reads it: "C4 · CH 1", "CC 74 · CH 2", "BEND · CH 3" (LearnedMessage::described()); text that is no message as it is.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::expression(int status, int data1, int data2)

    Emitted for a controller's expression while it plays: status is 0xE0 (pitch bend, data1 and data2 its low and high 7 bits, scaled), 0xD0 (pressure, data1) or 0xB0 (control change data1 at data2, never one EngineMidi::isChannelState() names), with no channel (Machine::sendLive()).

    [invokable] void MidiInput::forget(const QString &controller)

    Forgets all of controller's settings, hosting and the octave's link included: it starts again from the known defaults.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::knobMoved(int knob, qreal value)

    Emitted when a learned CC moved knob (0 to 2) to value, 0 to 1.

    [signal] void MidiInput::knobTurned(int knob, int delta)

    Emitted when a learned CC turned knob (3: the big knob) by delta detents.

    [invokable] void MidiInput::learn(const QString &controller, Midi::LearnTarget what)

    Takes the next note or CC from controller (any controller, when empty) as what is learned (what: a drum key or a control), reported by learned() rather than played; learning goes on until stopLearning().

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::learned(const QString &controller, const QString &message, int note)

    Emitted while learning, for the message controller sent ("note CH N", "cc CH N" or, learning a control, "bend CH", the channel 1 to 16); note is the note played, -1 for a CC or a bend. Nothing is stored: the asker stores it (setHit(), setControl()).

    [signal] void MidiInput::mixerControl(const QString &controller, const QString &control, int status, int data1, int data2)

    Emitted when a message learned as a MIXER control (control, a MixerControl id) came from the controller controller (its id): status its kind (0x90 or 0x80 a note, 0xB0 a CC, 0xE0 a pitch bend, no channel), data1 and data2 as sent.

    [invokable] QString MidiInput::noteName(int note) const

    Returns MIDI note's name, "C4" for 60 (LearnedMessage::noteName()).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void MidiInput::notePlayed(const QString &controller, int note)

    Emitted after pressed() for a key not learned as a drum row or pad: note played on controller (the name SETTINGS · MIDI shows), for the key watch (KeyWatch).

    [signal] void MidiInput::padsToggled()

    Emitted when a key learned as LIGHTPAD PADS went down: the Lightpad's pads for the drums and the chords go on or off.

    [signal] void MidiInput::pressed(int holder, int note, int velocity, int slot)

    Emitted when a key went down on a connected controller: holder names that key (the controller, its channel and the key, the same for its release), note is what it plays after the controller's transpose, velocity 1 to 127 after its velocity settings, slot the drum row or pad it was learned as (-1 without one). Studio plays it on the machine on screen (Machine::press(), Machine::Hold::Controller).

    void MidiInput::receive(const MidiMessage &message)

    Handles message from a controller: learns it, works the control it is learned as, or plays it. A hosted control surface's messages go to its driver first (setSurface()).

    void MidiInput::receive(const QString &connection, int size, quint8 byte0, quint8 byte1, quint8 byte2)

    Handles the message byte0 byte1 byte2 (size bytes) come on connection, as the multiplexer would hand it on (with no copy dropped): for the tests and the drivers' emulated messages.

    [signal] void MidiInput::released(int holder)

    Emitted when the key holder came up (a note-on with velocity 0 included), or its controller was unplugged: whatever it started ends (Machine::release()). Every pressed() gets one released().

    void MidiInput::setClock(const std::function<qint64 ()> &now)

    Reads the time (milliseconds) from now rather than from a clock of its own, so a test can say what time it is: the time tells a bridge's copy of a message from its repeat, and a press come again over another connection from a new one.

    [invokable] void MidiInput::setHit(const QString &controller, int note, int slot)

    Has controller's note play drum row (or pad) slot; a slot under 0 forgets the note. A note plays one slot, and a slot is played by one note.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void MidiInput::setOption(const QString &controller, const QString &option, int value)

    Sets controller's option to value: channel (1 to 16, 0 all), transpose (semitones, −48 to 48), velocity (1 to 127, 0 as sent), curve (0 as sent, 1 soft, 2 softer, 3 even: every touch at half velocity or more), pressure (0 as sent, 1 firm, 2 firmer: light presses send less, for a surface that reaches its top halfway; 3 light, 4 lighter: light presses send more, for one that needs a hard press to reach it), bendRange (the semitones its full bend is, 1 to 96), expression (0 off, 1 on), lights (0 off, 1 on: the learned MIXER keys' state sent back to it) or pickup (1: a fader takes a level over once it reaches it; 0: any move sets the level).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    void MidiInput::setSurface(const ControllerId &controller, const MidiInput::Surface &surface)

    Has the control surface controller's messages go to surface first (its driver, while hosted): what it takes is its own, and the rest works the controller's learned keys and knobs only, never plays (no notes, no expression). An empty surface ends it: the controller plays again.

    [invokable] void MidiInput::setSurfaceType(const QString &controller, const QString &type)

    Has controller hosted as a control surface by the driver type (mackie), or by none (empty): kept with its settings, read by ControllerDrivers.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] QVariantMap MidiInput::settings(const QString &controller) const

    Returns controller's settings: channel (0 all), transpose, velocity (0 as sent), curve, pressure, bendRange, expression (a bool), label, surface (the driver hosting it as a control surface, "" none), knobs (its endless knobs' encoding, "" told by their values), lights (a bool: the learned MIXER keys lit back), pickup (a bool: its faders take a level over once they reach it), hits (a note, as text, to its drum row or pad) and controls (a control id to its message).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

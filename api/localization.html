    Detailed Description

    Every text goes through KI18n: i18nc() and friends in C++, and in QML the same functions on the root context (KLocalization::setupLocalizedContext(), KF 6.8 and later; the bare names, not the org.kde.ki18n module, which the device's KF6 does not have). The catalogs are po/<lang>/ravving.po, compiled by ki18n_install into share/locale/<lang>/LC_MESSAGES/ravving.mo (build/locale/... in a build tree).

    language is stored in the profile (ravving/profile, ui/language) and applied before the first i18n call at start. Changing it switches at once: KI18n's language list is set, a LanguageChange goes to the application, and the QML bindings that call i18n are evaluated again (QQmlEngine::retranslate()); backend objects with translated properties catch the LanguageChange with an event filter on the application and emit their change signals. Texts created earlier and stored (a notice already emitted, an issue reported) keep their language until the next start, which restartAdvised signals.

    Member Function Documentation

    [explicit] Localization::Localization(QObject *parent = nullptr)

    Sets KI18n's domain, the build tree's catalogs and the saved language, with the given parent. Make it right after the application object and before any i18n call.

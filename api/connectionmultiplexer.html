    Detailed Description

    A controller plugged in several ways at once (a cable's two ports, its radio beside its cable; a port bridged twice) sends each message on each. The multiplexer keeps, for each controller, which connection each message last came on and when: the same message from another of its connections within CopyWindowMs is that one come the other way, and dropped. A message from the same connection again is never dropped (an endless knob's identical ticks), nor is anything from a controller with one connection. This is the one place copies are told from repeats; what reads the stream (MidiInput, the drivers) sees each message once. Time comes from its own clock, or the one given (setClock()).

    Detailed Description

    Zynthbox runs no NetworkManager, so this works on what it has:

    • on and off: Zynthbox's own user services (zynthbox-wifi-manager-start and -stop, set_wifi.sh); the choice is saved as ZYNTHIAN_WIFI_MODE and restored when ravving starts, because Zynthbox's wifi-setup.service, a oneshot unit, starts wpa_supplicant at boot but has it killed with its cgroup as soon as it finishes;
    • saved networks: Zynthbox's wpa_supplicant.conf (WpaConfig), which set_wifi.sh copies into place on every start; a join saves the network there first, so it is joined again at the next boot and zynthbox-qml and webconf, which read the same file, see it;
    • state, scans and joins: wpa_supplicant itself, through wpa_cli on wlan0.

    The state is polled while active (every 2 s, faster while switching or joining), and the networks are rescanned every 15 s while scanning is set. A join that has not succeeded in time has failed (a wrong passphrase, out of range). Commands run asynchronously. Without a wlan0 (a desktop run) the state is unavailable. GUI thread only.

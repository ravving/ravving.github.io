    Machine Class

    The base of every machine of the studio (a drum machine, the bass, the chords, the samplers): an instrument on one libzynthbox sketchpad track, playing a pattern of steps from its PatternModel through its sound engine. More...

    Detailed Description

    Subclasses (DrumMachine, MonoMachine, ChordMachine, SamplerMachine, PadSamplerMachine) say what a step holds and how it sounds, through the protected virtual functions declared in machine.h (onAttached(), refresh(), revoice(), clearOwnSteps(), applyChart(), chart(), restoreContent(), placeHit(), liveNotes(), liveVelocity(), sectionHasNotes()). This class has the rest:

    • the track: level (its gain handler), pan and SOUND EFFECTS (TrackEffects), mute, the strip's pause, and the LIVE FX kick cuts (setKickMode());
    • the pattern: its length in bars, the bar on screen, the playhead, the STEP entry cursor, the bar loop and ONCE, and the two clips SECTIONS change between on the bar line (attachSpare(), cueSectionContent());
    • the sound: the sources it can play through (its own engine, soundfont instruments, other engines), the engine's factory sounds, the SOUND MODIFIERS (SoundControls) and the sounds the user saved (MY SOUNDS);
    • presets from a PresetLibrary (charts of one character per step, per row), the loaded one marked edited after any change;
    • LIVE: playLive() and stopLive() sound a key at once, recordLive() writes it at the step nearest the transport (a take), writeAtCursor() at the cursor (STEP entry). A key is whatever the subclass plays: a drum row, a MIDI note, a chord degree;
    • AUTO: knob moves recorded into the pattern step by step and played back;
    • undo: the pattern takes part in the project's History as a HistoryParticipant.

    The project file keeps state() for each machine. Without libzynthbox (a desktop run) the same API works on the subclass's own storage. Everything runs on the GUI thread.

    [read-only] canUndo : bool

    This property holds whether this machine's pattern has a change to undo.

    UNDO and REDO cover the pattern (steps, notes, chords, bars, the samplers' slots and their automation): every change is a step of the project's History, changes within half a second of each other are one step, and a take recorded live is one step (TakeRecorder groups it). The mix, the sound, the effects and what is on screen (a sampler's bank) are not part of it. Opening a project starts it afresh.

    Member Function Documentation

    Machine::Machine(const QVariantMap &config, const QVariantMap &state, PresetLibrary *presets, GlobalEffects *globalEffects, QObject *parent = nullptr)

    Constructs a machine from config, its object in kits.json (key, track, zynthianChannel, engine, the optional sound, sources, soundPresets and defaultPreset...), and state, what the project saved for it (state(); empty for a fresh project). presets is its preset library and globalEffects the studio's send effects, which its TrackEffects feed. parent is the QObject parent. The subclass calls restoreContent() from its own constructor.

    QVariantMap Machine::activeExpressions() const

    Returns the live expressions of the source playing, as a map of name to a map with symbol and max.

    [override virtual] void Machine::applyHistoryState(const QVariantMap &state)

    Reimplements: HistoryParticipant::applyHistoryState(const QVariantMap &state).

    Puts the pattern part state back, keeping what is on screen.

    void Machine::applyPreset(const QVariantMap &chart, const QString &name, const QVariantMap &sound = {}, bool withBars = true)

    Replaces the pattern with a preset's chart under the name name (a library's, or one read from a USB stick without taking it in: PresetExchange::loadStickPattern()), after putting back the parts of sound (applySoundParts(); empty: the sound stays). With withBars its length is taken too, else it is laid over the bars the machine has.

    void Machine::applySectionContent(const QVariantMap &content)

    Takes a section's content back: the pattern becomes it, the sound stays and the history starts over. An empty map (a section with nothing of this machine yet) empties the pattern.

    [virtual] void Machine::applySoundParts(const QVariantMap &parts)

    Puts back only the parts of a sound parts has (any subset of soundState()'s keys: a pattern preset's sound, PresetLibrary); the other parts stay. A source (a drum machine's kit) this device does not have leaves that part alone, with a line in the log.

    void Machine::applySoundState(const QVariantMap &state)

    Puts back the whole sound state (MY SOUNDS): a part it lacks goes to its default. A source change restarts the engine; the MODS reach it once it is up.

    void Machine::attach(QObject *pattern, SketchpadTrack *track, QObject *playGridManager, QObject *syncTimer, QObject *gainHandler)

    Starts playing through libzynthbox: pattern (the PatternModel of this machine's track, clip a) holds the steps from now on, track routes it, playGridManager makes notes, syncTimer plays live notes and gainHandler is the track's level. Its effects attach to the track's passthrough on their own (effects()). Calls the subclass's onAttached().

    void Machine::attachSpare(QObject *pattern)

    Gives the machine its track's other clip, pattern (clip b), with which it takes turns for SECTIONS on the bar line.

    void Machine::beginEditGroup()

    Makes every change until endEditGroup() one step of the history (a take); groups nest.

    [virtual] void Machine::checkSaved(const QVariantMap &state) const

    Notes for the issues center (ProjectCheck::miss()) what the saved state names that the machine could not resolve: its sound source, factory sound, MODS knobs and their automation lanes; a subclass adds its kit or samples. The studio calls it after the machine took the state; it only looks at what is loaded.

    int Machine::clip() const

    void Machine::cueSectionContent(const QVariantMap &content, int span, bool intoSpare)

    Takes a section's content, span bars long, while the transport plays. With intoSpare it is written into the clip that does not play and the two change places, so nothing in the playing clip drops or doubles; otherwise (picked again before the bar) into the clip already waiting. The model and the screen take the section at once; the studio switches the clips on the next bar, and the pause with them.

    [invokable] void Machine::loadPreset(const QString &name, bool withSound = false, bool withMods = false, bool withBars = true)

    Replaces the pattern with the preset name, as the presets dialog says: withSound (WITH ITS SOUND) also puts back the source or kit the preset keeps, withMods (WITH ITS MODS) the MODS it keeps (PresetLibrary::soundParts(); MODS it does not keep stay as they are), and withBars (WITH ITS BARS) takes its length too, else the pattern is laid over the bars the machine has (PresetLibrary::fitChart()).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Machine::loadSound(const QString &name)

    Puts back the saved sound name (applySoundState()); unknown names do nothing.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Machine::loadSoundPreset(const QString &name)

    Loads the factory sound name into the engine, all its ports but those the machine keeps for itself (kits.json soundPresets.keep); the SOUND MODIFIERS follow it. It is kept with the project and sent again whenever the engine restarts (soundPresetControls()). An empty name goes back to the machine's own sound: the plugin's start-up sound (soundPresets.base), the engine's controls from kits.json, and the SOUND MODIFIERS at their defaults.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Machine::recordLive(int key, bool accented)

    LIVE with REC: plays the live key and writes it, accented when accented is true, at the step nearest the transport's position. With quantise off it keeps its distance from that step. The hit is written once the playhead has left its step, so the sequencer does not play it a second time.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Machine::redo()

    Goes forward again one change of this machine's pattern (History::redoIn()).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    Detailed Description

    repeat() anchors at the start of the current 16th (SyncTimer's grid, sample accurate through ZynthboxBridge::timerTickAtFrame()); that step plays out live, then the audio from the anchor repeats every steps 16ths until stop(). Calling repeat() again while repeating changes only the length; the anchor stays. With the transport stopped it repeats the last steps of audio at once. Without a bridge the tempo is taken as 120 BPM.

    The signal processing is a RepeatCore (the seams, the crossfades, the history and the slice), which the tests run without JACK. The audio thread reads only atomics and preallocated buffers. debugState() reads what the GUI thread last asked for and what the audio thread last did, for a fifo call while a pad misbehaves; the ravving.livefx logging category traces the GUI thread's calls.

    After the repeat the same callback runs a LiveFxEngine, the punch-in effects on the mix: setEffects() switches them and syncGrid() gives it the bar under way and the tempo, so its beat-synced ones land on the transport's grid.

    Being the first stage after the master, it also passes on only sound (RepeatCore::MaxSample): a sample that is not finite, or beyond 16 times full scale, is passed on as silence. libzynthbox's sampler can read past a one-shot's end (the metronome's tick ended on two samples near 10^12), and the LV2 inserts after this stage then blank the whole block, which cuts the sound with a click.

    The client also watches the graph's dropouts: JACK's xrun callback counts them, except within 3 s of a client or link change and in the first 20 s after the start (the graph is rebuilding then), and every minute five or more raise an "Audio dropouts" issue.

    Member Function Documentation

    [explicit] BeatRepeat::BeatRepeat(ZynthboxBridge *bridge, QObject *parent = nullptr)

    Opens and activates the JACK client with its buffers, with the given parent; bridge gives the tempo and the step grid (null leaves the repeat unsynced). Without JACK, isValid() returns false.

    QString BeatRepeat::debugState() const

    Returns one line of the repeat's and the engine's state, for a call over the fifo while a pad misbehaves: the pads' last requests (the anchor and length repeat() last gave the core, the effects mask), the audio clock now, and what the audio thread last did (its last cycle's start frame and the peaks of that cycle into the repeat, out of it and out of the engine). Also written to the log.

    quint64 BeatRepeat::frameNow() const

    Returns the current JACK frame (jack_frame_time(), the clock AudioLevels' recording frames and SyncTimer's playback start are counted in); 0 without a client. Exporter places its recording with it.

    void BeatRepeat::repeat(double steps)

    Repeats every steps 16ths (1 for a repeated 16th, 0.5 and 0.25 for 1/32 and 1/64 ratchets, 4 for a beat) from the step under way, or changes the length of the repeat running. The length is clamped to 16 frames .. 5.4 s. Does nothing without a client.

    int BeatRepeat::sampleRate() const

    Returns the sample rate of the JACK server this client runs on; 0 without a client.

    void BeatRepeat::setEffects(quint32 mask)

    Switches the engine's effects to mask, a LiveFxEngine::bit() per effect on (of its heads, REVERSE to WOBBLE, only the first set plays). Does nothing without a client.

    void BeatRepeat::stop()

    Returns to the live input, over the 300 ms release.

    void BeatRepeat::syncGrid()

    Gives the engine the transport's grid as it is now: the frame the bar under way started at (the current frame while the transport is stopped) and a 16th's length at the current tempo. Does nothing without a client.

    Detailed Description

    The list (outputs) is PipeWire's audio sinks, read with pw-dump: the jacks (the HiFiBerry, the default) first, then Bluetooth, HDMI and the rest. current is the one in use.

    The jacks are the graph's clock: the master is wired straight to their ports (JackWiring). Any other sink is fed through ravving's own loopback: pw-loopback creates a virtual sink ravving-out whose playback stream targets the chosen sink with 2048 frames of buffering, and the master is linked to it with pw-link, so the studio keeps its clock on the jacks and the Bluetooth link gets its own buffering. Meanwhile the jacks are muted (wpctl set-mute on their sink), not unlinked: PipeWire suspends an unlinked ALSA sink, the Bluetooth sink would then drive the whole graph, and a stall of the Bluetooth transport would silence everything. Making the Bluetooth sink the default sink would have the same effect.

    The output chosen with select() is saved in the settings (ravving/outputs): when it goes away the sound falls back to the jacks (fallBack()), and when it returns (at start, on a reconnection: refreshSoon()) the sound goes to it again, once its Bluetooth codec matches preferSbcXq. Selecting the jacks clears the choice. An OutputWatch checks that the loopback plays what the master sends: when it plays silence the route is rebuilt once, then a "plays no sound" issue is reported. A Bluetooth device connected with its headset profile only is reported too.

    The music player follows currentSink, since it plays beside the graph rather than through the master. External commands run asynchronously (runCommand()); GUI thread only. Output names are translated again on a language change.

    preferSbcXq : bool

    This property holds whether a Bluetooth output plays through SBC-XQ (SBC at its highest bitpool, about 550 kb/s against 350) when the device offers it, else plain SBC. Kept in the settings; true by default. Changing it switches the device playing at once.

    Member Function Documentation

    [explicit] AudioOutputs::AudioOutputs(Studio *studio, QObject *parent = nullptr)

    Constructs the outputs of studio (whose master ports are linked to the loopback), with the given parent; reads the kept choice and starts looking for its sink (refreshSoon()).

    void AudioOutputs::fallBack()

    Sends the sound back to the jacks because the output in use went away; the choice is kept for its return.

    [signal] void AudioOutputs::notify(const QString &text, const QString &color)

    Emitted with a short translated status text, such as "PLAYING THROUGH THE JACKS" or "COULD NOT ROUTE THE OUTPUT", and its color (a CSS colour).

    [invokable] QString AudioOutputs::outputForAddress(const QString &address) const

    Returns the name of the output of the Bluetooth device at address (compared without case); empty when it has no sink yet.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    QString AudioOutputs::preferredAddress() const

    Returns the Bluetooth address of the selected output; empty for the jacks or any other output. Bluetooth reconnects that device when the adapter comes on, since its sink exists only while connected.

    [invokable] void AudioOutputs::refresh()

    Reads PipeWire's sinks again (asynchronously; outputsChanged() follows when they changed), then falls back to the jacks when the output in use is gone, routes again when its node was replaced (a profile or codec change), returns to the kept output when it is back, unmutes jacks left muted, and applies the codec preference.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    void AudioOutputs::refreshSoon()

    Reads the sinks now and five more times 1.5 s apart: a device that just connected lists its sink a moment later.

    void AudioOutputs::releaseJacks()

    Unmutes the jacks at once, blocking for up to 1.5 s, when another output has them muted. Called on the way out: ravving leaves with _exit, so its destructors never run.

    [invokable] bool AudioOutputs::sbcXqFor(const QString &address) const

    Returns whether the device at address plays through SBC-XQ: its own choice in sbcXqByDevice, else preferSbcXq.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    See also setSbcXqFor().

    [invokable] void AudioOutputs::select(const QString &name)

    Sends the sound to the output name (jacks for the device's own) and saves it as the chosen output. A Bluetooth output is routed once its codec is settled (by refresh()).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void AudioOutputs::setSbcXqFor(const QString &address, bool sbcXq)

    Sets the device at address to SBC-XQ (sbcXq true) or plain SBC, over preferSbcXq. When that device is the output in use its profile is switched at once, which renegotiates its stream; some devices drop the connection on a renegotiation.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    See also sbcXqFor().

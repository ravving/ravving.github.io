    Detailed Description

    Nothing of ravving's lands in zynthbox-qml's folders (its sketchpads, samples, capture...) and nothing of zynthbox-qml's is touched: ravving reads the device's sample library and writes only here. Four roots, each for one kind of file, follow the XDG base directories:

    RootWhereWhat
    config$XDG_CONFIG_HOME/ravvingsettings (QSettings: the input set-up, the interface's choices)
    state$XDG_STATE_HOME/ravvingthe live session (session.json, libzynthbox's sequence): device-local, rebuilt from a project
    cache$XDG_CACHE_HOME/ravvingwhat can be rebuilt: reversed samples, raw takes, lv2-ports.json
    library/zynthian/zynthian-my-data/ravving on the device (the data partition every Zynthbox has), $XDG_DATA_HOME/ravving on a desktopthe user's own work, kept across reinstalls and shared over webconf

    The library holds projects/ (named projects), templates/ (Templates), presets/ (the user's pattern presets, <machine>-presets.json), samples/ (with takes/, recordings/ and imported/), soundfonts/, midi/, recordings/ (the master's, MixRecorder), videos/ and exports/ (tracks with their covers and sidecars, and .ravv bundles).

    For development and tests, RAVVING_HOME puts all four roots under one folder and RAVVING_LIBRARY moves the library alone; RAVVING_PROJECT_DIR (the session folder) and RAVVING_PROJECTS_DIR are honoured too.

    initialise() reads the environment once, before QGuiApplication reads the XDG variables (main() points them at the bundled theme after it), moves files found in the legacy layout (~/.local/share/ravving's project, presets and caches; takes in zynthbox-qml's samples folder; recordings in its capture folder) into these folders, rewriting the paths the session and the projects refer to, and makes the folders. The getters only read what initialise() decided and are thread-safe after it.

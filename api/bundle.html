    Detailed Description

    ravving ships as an AppImage for the Zynthbox Store. The AppImage's AppRun starts this program, which lives beside ravving in the bundle (usr/bin/ravving-setup next to usr/bin/ravving, the data in usr/share/ravving, the unit in etc/systemd/user).

    Every action runs default-app.sh, the deployment script that ships in the bundle, from the bundle's own copy, so the script always matches the files it installs:

    • tryIt(): install the bundle, then switch to ravving for this session (install, then run ravving); Zynthbox is back at the next boot;
    • makeDefault(): install, then make ravving the UI that starts at boot (ravving);
    • restoreZynthbox(): Zynthbox starts at boot again, ravving stays installed (zynthbox);
    • purge(): the same, and ravving's files leave the system (zynthbox --purge); projects and recordings stay.

    tryIt() and makeDefault() skip the install when the bundle's version is already the installed one, and install nothing when canStart is false.

    The script detaches the switching commands into a transient systemd unit, because switching stops zynthbox-qml's service and with it this program (the Store starts it inside that service). The status (which UI starts at boot, which one runs, what is installed) comes from the script's status command, read again after every action. The scripts run as asynchronous QProcesses; the callbacks run on the GUI thread.

    Member Function Documentation

    [explicit] Bundle::Bundle(QObject *parent = nullptr)

    Finds the bundle, checks it is valid and that this is a Zynthbox, and reads the status when both hold; otherwise message says why nothing can be done. parent is the QObject parent.

    [invokable] void Bundle::checkRequirements()

    Checks what the device lacks (default-app.sh deps <bundle> --json) and updates missing, packages and canStart. Does not set busy, so actions stay available while it runs.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::installRequirements()

    Installs the missing packages with apt-get (default-app.sh deps --install, which needs the network) and checks again.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::makeDefault()

    Installs the bundle when needed, then makes ravving the UI that starts at boot.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::purge()

    Makes Zynthbox the UI that starts at boot again and removes ravving's files from the system.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::refresh()

    Reads the status again (default-app.sh status); the first time, it also checks the requirements.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::restoreZynthbox()

    Makes Zynthbox the UI that starts at boot again; ravving stays installed.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bundle::tryIt()

    Installs the bundle when needed, then switches to ravving for this session.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    Detailed Description

    The modal layers up, how the device's knobs work, and the UI icons' sources (icon(), iconIn(), withIcons()). No control reaches into the app's objects.

    Property Documentation

    inputBlocked : bool [read-only]

    The modal layers up (the dialogs, the MENU drawer, a drop-down's list), and whether any is. The modal dimmer stops items (buttons, MouseAreas) under a dialog, but not pointer handlers: Qt Quick hands a press to every handler under it even after an item above took it, and a DragHandler then takes the drag over. So every handler on a page binds enabled: !Interaction.inputBlocked (the app's Session.inputBlocked reads this one; tools/check-handlers.py checks it); disabling the page instead would close the drop-downs on it (a disabled ComboBox shuts its list). Kept by identity, not counted, so a layer reported up twice (an open() repeated) or down twice cannot leave the page blocked.

    knobMode : string

    How a fixed pot takes over a value it does not sit on (PickUp): pickup, jump or scale. The app sets it from the user's profile (SETTINGS · DEVICE).

    knobsAbsolute : bool

    Knobs 1–3 are fixed pots (the Z2_V5B kit): a control they drive waits for its pot to pass its value before following (PickUp). The app sets it from the device.

    openDialogs : int

    How many dialogs (Dialog) are up: the drawer closing under one leaves it the keys.

    overlays : list<QtObject>

    The modal layers up (the dialogs, the MENU drawer, a drop-down's list), and whether any is. The modal dimmer stops items (buttons, MouseAreas) under a dialog, but not pointer handlers: Qt Quick hands a press to every handler under it even after an item above took it, and a DragHandler then takes the drag over.     Signal Documentation

    getMoreRequested(string kind, string group)

    GET MORE was asked for from a picker: the dialog opens on kind (a Store kind, such as "patterns" or "skins") with group's rows first (a pattern group, a machine's key; ""). The app answers it (ControlCenter: StorePopup).

    Note: The corresponding handler is onGetMoreRequested.

    pageFocusRequested()

    The page should take the keys back (a dialog closed and what had them is gone): the app answers it (Main.qml: the page on screen takes the focus).

    Note: The corresponding handler is onPageFocusRequested.

    Method Documentation

    icon(name)

    The source of the UI icon name in the icon set picked (Theme.iconSet), white: for a button's icon.source or an IconImage, which tint it. iconIn() draws it in an ink (an Image, an <img> in a Text); Icon shows one on its own.

    iconIn(name, ink)

    The source of the UI icon name in the icon set picked, drawn in ink.

    keyIcon(key)

    The icon withIcons() draws for the character key ("" for none).

    overlayShown(layer, shown)

    A modal layer (layer) came up or went (shown).

    withIcons(text, ink, size)

    The device's keys named in a hint or a notice (text: "▲ ▼ pick · SELECT opens", "FILES → SEND…", "✓ ON DEVICE") as StyledText, each key's or mark's character drawn as its icon, size pixels square in ink. The strings keep the characters, so translations need no markup; the rest of the text is escaped. A Text showing it sets textFormat: Text.StyledText.

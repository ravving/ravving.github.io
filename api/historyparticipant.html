    Detailed Description

    A participant names itself (historyKey(), historyLabel()) and hands its state over (historyState()) and back (applyHistoryState()). The machines are participants (Machine); another object joins by implementing the four functions, calling History::add() once and History::record() after each change.

    The state is plain data (what JSON can hold) and must compare equal when nothing that matters changed: leave out what only describes the view.

    [pure virtual] void HistoryParticipant::applyHistoryState(const QVariantMap &state)

    Replaces the participant's state with state, a value historyState() returned (an undo or a redo). The participant may emit its usual change signals: History does not record changes while it applies a state.

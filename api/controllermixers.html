    Detailed Description

    The app tells it each strip's instrument as it changes (setStrip(), from MixerLink.qml: a change from the screen, the device's keys, a project opened, a section switched) and the transport (setTransport()); it hands each to every controller, and the whole mix to one that starts later (a Bluetooth controller connecting again). A strip with no instrument set is empty (MixerStrip::present). The strips' controls come back as levelRequested(), panRequested(), muteRequested(), soloRequested(), recordRequested() and stopRequested(), a transport key's as pauseRequested() and the page keys' as pageStepRequested(), which the app does as its own controls would. ControllerDrivers attaches each driver while it runs (a ControllerHub). A controller plugged in several ways at once is one controller here (ControllerDrivers, LearnedMixers: one per ControllerId), its messages told from their copies before they reach it (ConnectionMultiplexer). GUI thread only.

    [invokable] void ControllerMixers::setStrip(int strip, const QVariantMap &state)

    Strip strip (0 up) shows an instrument whose state is a map of level (0 to 1), unity (the level at 0 dB), pan (−1 to 1), muted, soloed, paused and take (MixerStrip::Take: 0 none, 1 counting in, 2 recording); every controller is told when it changed.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    See also strip().

    [invokable] void ControllerMixers::setTransport(bool playing, int recording, bool paused = false)

    The transport is playing or paused, with a take or LIVE REC at recording (MixerStrip::Take: 0 none, 1 counting in, 2 recording); every controller is told when it changed.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

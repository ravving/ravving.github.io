    Detailed Description

    The process runs on a pseudo-terminal, so it dies with ravving (which leaves through _exit()); it is restarted when it crashes, with its startup commands sent again after every start; and every command is a transaction that ends at the prompt. This class gives that a typed C++ interface; ProcessWrapper is reached through Qt's meta-object system, like the rest of libzynthbox.

    Every run() gets a ProcessWrapper of its own. ProcessWrapper's own restart in place stops the old process with a 0 ms timeout, so its pty process is deleted while still running, and keeps the old process's unfinished transactions queued in front of the new one's startup, which can crash ravving (a drum kit changed twice while playing). Instead the old process is stopped properly (SIGTERM, then SIGKILL) and its wrapper is discarded with whatever it still had queued. GUI thread only.

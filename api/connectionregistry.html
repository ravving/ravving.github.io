    Detailed Description

    A port's name says what it is (keyOf(), transportOf(), isSendSide()): PipeWire's bridge prefix and underscores go, so a message's name and the list's name are one key; a Bluetooth MIDI device is two ports, "<device>:out" (what it plays: the connection) and "<device>:in" (what is sent to it: the connection's send target); ALSA's loopback, the device's own serial MIDI and PipeWire's empty Bluetooth node are no controllers (isController()).

    The connections of a known controller (ControllerProfiles: a label) are one Controller whichever way they come (a cable's several ports, its radio beside its cable); any other connection is a controller of its own, named by its key. Each controller has a primary connection, the one what is sent to it goes through (sendTarget()): a cable before Bluetooth, the first plugged in among equals; it moves when that one goes or a better one comes (connectionsChanged()). A controller is added with its first connection (controllerAdded()) and removed with its last (controllerRemoved()).

    With a router, every controller's channels are kept parked on ParkedTrack as it comes, so its raw notes reach MidiInput only. GUI thread only.

    [explicit] ConnectionRegistry::ConnectionRegistry(const QString &profilesFile = QString(), int *router = nullptr, QObject *parent = nullptr)

    Reads the known controllers from profilesFile (data/midi-devices.json) and follows router's controllers (null on a desktop: none, until add() says so), with parent.

    void ConnectionRegistry::add(const QString &name)

    The port name is plugged in: a connection of its controller, the controller itself when it is its first. A port that is no controller (isController()) is nothing.

    [signal] void ConnectionRegistry::connectionsChanged(const ControllerId &id)

    The controller id gained or lost a connection, and stays plugged in; its primary connection may have moved (sendTarget()).

    Controller ConnectionRegistry::controller(const ControllerId &id) const

    [signal] void ConnectionRegistry::controllerRemoved(const ControllerId &id)

    QList<ControllerId> ConnectionRegistry::controllers() const

    The list of controllers (ids) changed.

    Note: Notifier signal for property ids.

    [invokable] QVariantMap ConnectionRegistry::describe(const QString &id) const

    Returns the controller id for QML: id, title (Controller::title()), label, bluetooth (reached over Bluetooth only) and connections, a list of maps with each connection's name, transport (usb, bluetooth, serial or virtual) and primary.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    const Controller *ConnectionRegistry::find(const ControllerId &id) const

    Returns the controller id, null when it is not plugged in. The pointer is good until the next add() or remove().

    ControllerId ConnectionRegistry::idOf(const QString &name) const

    Returns the id of the controller behind the connection name (as the router lists it or as a message names it, plugged in or not): its profile's label, else its key.

    [static] bool ConnectionRegistry::isController(const QString &name)

    Returns whether the port name is a controller: not ALSA's loopback ("Midi Through"), not the device's own serial MIDI ("ttymidi"), not PipeWire's Bluetooth MIDI node ("BLE MIDI n", there with nothing paired), and not a Bluetooth device's send side (isSendSide()).

    [static] bool ConnectionRegistry::isSendSide(const QString &name)

    Returns whether the port name is only the way to a Bluetooth MIDI device: PipeWire shows one as two ports, "<device>:out" (what it plays, the connection) and "<device>:in" (what is sent to it).

    [static] QString ConnectionRegistry::keyOf(const QString &name)

    Returns the connection name's key: the same for the router's list ("Midi-Bridge:USB Composite Device MIDI 1") and the messages ("Midi_Bridge:USB_Composite_Device_MIDI_1"), with the bridge's prefix gone, underscores as spaces and no slash (a settings group's name).

    [signal] void ConnectionRegistry::plugged(const QString &title)

    A controller is plugged in, shown as title (Controller::title()); emitted with controllerAdded() for QML.

    const ControllerProfiles &ConnectionRegistry::profiles() const

    Returns the known controllers' profiles.

    void ConnectionRegistry::remove(const QString &name)

    The port name was unplugged: its controller loses the connection, and goes with its last.

    [static] QString ConnectionRegistry::sendSideOf(const QString &name)

    Returns the port that reaches the controller on the connection name: a Bluetooth MIDI device's "<device>:in" for its "<device>:out", the name itself for any other.

    QString ConnectionRegistry::sendTarget(const ControllerId &id) const

    Returns the port what is sent to the controller id goes to (its primary connection's send target), empty while it is not plugged in.

    [static] Transport ConnectionRegistry::transportOf(const QString &name)

    Returns how the connection name reaches ravving, from its name: Bluetooth for PipeWire's "<device>:in" and "<device>:out" ports, Serial for the device's own serial MIDI (ttymidi), Virtual for ALSA's loopback (Midi Through), Usb for any other.

    [signal] void ConnectionRegistry::unplugged(const QString &title)

    The controller shown as title is gone; emitted with controllerRemoved() for QML.

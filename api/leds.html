    Detailed Description

    QML passes the whole picture as a map of button name to colour:

    
 leds.setButtonColors({ step1: "#e07708", num2: "white", play: Qt.rgba(0, 1, 0, 1) })

    Buttons left out show the dim inactive colour (blue at 1/255, times the brightness); a null, empty or transparent colour turns one off. Colours are scaled by the LED brightness setting shared with zynthbox-qml (UI/ledBrightness, 1 to 100 %, 15 by default) and written to the strip at the next turn of the event loop, coalesced.

    Button names: menu, num1 to num5, star, mode, step1 to step16, alt, record, play, metronome, stop, back, up, select, left, down, right, global. On the Z2_V4 kit only step1 to step5 have LEDs. The button-to-LED tables match libzynthbox's ZynthboxBasics.

    The strip is a WsLedStrip of ZYNTHBOX_LED_COUNT LEDs; on start the boot rainbow (rainbow-leds.service) is stopped.

    Property Documentation

    [read-only] available : const bool

    This property holds whether the LED strip could be opened; false on a desktop or when ZYNTHBOX_LED_COUNT is unset.

    Member Function Documentation

    [explicit] Leds::Leds(QObject *parent = nullptr)

    Opens the LED strip when ZYNTHBOX_LED_COUNT is set, reads the brightness, stops the boot rainbow and schedules the first write, with the given parent. When the SPI device cannot be opened it reports a "No key lights" issue and stays unavailable.

    [invokable] void Leds::allOff()

    Turns every LED off at once, cancelling a pending write. Called on exit and by the destructor.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Leds::setButtonColors(const QVariantMap &colors)

    Replaces the colour of every button with colors, a map of button name to colour (a QColor or a colour string); see the class description. Ignored when unavailable or unchanged.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

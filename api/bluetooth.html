    Detailed Description

    Built on BluezQt (BlueZ over D-Bus): a Manager for the adapter and the devices, a pairing agent with the DisplayYesNo capability, an ObexManager with Object Push sessions for sending, and an OBEX agent for receiving. Received files are saved in the library's incoming folder, renamed with a number when the name is taken, and announced with fileReceived().

    Audio devices are played through over A2DP. When one connects, WirePlumber creates its sink (bluez_output.<address>.1); useAsOutput() hands that sink to AudioOutputs, which routes the master to it. Disconnecting, forgetting or quitting sends the sound back to the jacks.

    Connecting a device that does not answer the page is retried after 2, 5 and 10 s. BlueZ registers one local A2DP endpoint per codec, shared by every device, so only one audio device streams a given codec at a time: a device refused while another audio device is connected is handed the link (the other is disconnected and the connection retried). When the adapter comes on, the output AudioOutputs kept is connected once if no other audio device is connected.

    Scans last 12 s and find classic (BR/EDR) devices only; see startDiscovery().

    devices is rebuilt 150 ms after any BlueZ change; pairing and transfer are set by the agents. state is unavailable, with reason, until BlueZ answers. GUI thread only, with asynchronous D-Bus calls; outcomes are reported with notify().

    [read-only] busy : QVariantMap

    This property holds the operation under way per device, as a map of address to pairing, connecting, waking (paged again: it did not answer), switching (another audio device is disconnected for it), disconnecting or routing, until it succeeds or fails. Clearing an entry (disconnectDevice(), forget()) also cancels the pending retries.

    [read-only] devices : QVariantList

    This property holds the devices known or in range, connected ones first, then paired ones, then by signal strength. Each is a map with the keys address, name, kind (phone, computer, audio, input or other), paired, connected, trusted, rssi, audio (it can play) and receives (it can take a file).

    This property holds the pairing request waiting for an answer: an empty map, or one with address, name, kind and passkey. kind is confirm (the passkey shown on both sides, to accept or reject), pin (a PIN to enter), passkey (a number to enter) or display (the passkey to enter on the other device). answerPairing() replies.

    Member Function Documentation

    [explicit] Bluetooth::Bluetooth(QObject *parent = nullptr)

    Starts BluezQt's managers asynchronously and registers the pairing and receiving agents, with the given parent. Without OBEX, an issue is reported that files cannot be sent or received.

    [invokable] void Bluetooth::answerPairing(bool accept, const QString &text = QString())

    Answers the pending pairing request: accept to accept or reject it, and text for the PIN or passkey entered.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] bool Bluetooth::audioConnected() const

    Returns whether an audio device is connected (its audio breaks up during a scan).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::cancelTransfer()

    Cancels the transfer running.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::connectDevice(const QString &address)

    Connects the paired device at address: paged again while it does not answer, and handed the audio link when another audio device holds it (see the class description).

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] QVariantMap Bluetooth::device(const QString &address) const

    Returns the device at address as in devices; an empty map when unknown.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::disconnectDevice(const QString &address)

    Disconnects the device at address, sending the sound back to the jacks if it played through it; for a device still being connected, cancels the pending retries.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void Bluetooth::fileReceived(const QString &path)

    Emitted when a file sent to this device arrived complete at path.

    [invokable] void Bluetooth::forget(const QString &address)

    Unpairs and removes the device at address, cancelling its pending retries and sending the sound back to the jacks if it played through it.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void Bluetooth::notify(const QString &text, const QString &color)

    Emitted with a short translated status text, such as "PAIRED · <name>", and its color (a CSS colour). Also written to the journal.

    [invokable] void Bluetooth::pair(const QString &address)

    Pairs with the device at address, then trusts it (so it may connect on its own) and connects it. A device already paired is only connected.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::sendFile(const QString &address, const QString &path)

    Sends the file at path to the device at address over OBEX Object Push; transfer tracks it. Refused, with a notify(), when there is no file, no OBEX, or a transfer is still running.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::setDiscoverable(bool on)

    Makes the device discoverable and pairable for three minutes when on is true; hides it otherwise.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    See also discoverable().

    [invokable] void Bluetooth::setOn(bool on)

    Powers the adapter on when on is true, off otherwise, unblocking the radio first (rfkill unblock bluetooth) when switching on. The adapter is kept while it is off, so it can be powered back on. Without an adapter it unblocks the radio and starts the service instead.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    void Bluetooth::setOutputs(AudioOutputs *outputs)

    Sets the outputs through which useAsOutput() routes the master to a device's sink.

    [invokable] void Bluetooth::startDiscovery()

    Scans for 12 s, for classic (BR/EDR) devices only: speakers, headphones, phones and computers offer A2DP and OBEX there, while a dual-mode speaker found by its LE advertisement would pair only its LE Audio side. An inquiry shares the radio with any audio link, which breaks up while it runs. Does nothing when off or already scanning.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::stopDiscovery()

    Stops the scan.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Bluetooth::useAsOutput(const QString &address, bool on)

    Plays through the audio device at address when on is true: connected first if it is not, then routed once PipeWire lists its sink (asked again every second, for up to 15 s). With on false the sound goes back to the device's own output, which becomes the output kept.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

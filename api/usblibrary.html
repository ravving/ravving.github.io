    Detailed Description

    scan() mounts the stick and walks it in a worker thread, sorting what it finds by kind:

    KindWhat
    samplesWAV, FLAC, AIFF and Ogg files anywhere (not under ravving/exports)
    tracksaudio under ravving/exports (exported tracks, MP3 included)
    soundfontsSF2 and SF3
    projects.ravv bundles
    midi.mid and .midi
    presetsravving preset files under ravving/presets (pattern presets, saved sounds and templates: PresetExchange, which also lists the device's)

    The kinds are one table in the .cpp (suffixes on each side, the stick folder, the library folders listed and imported into, how it moves): adding a kind is one row there.

    Files are found wherever they are, the stick's standard layout (ravving/samples, ravving/soundfonts, ravving/projects, ravving/exports, ravving/midi) first; hidden and system folders (System Volume Information, FOUND.000, $RECYCLE.BIN) are skipped, and the walk stops after 20000 files so a full disk cannot stall it.

    importEntry() brings one in: samples to library/samples/imported/<stick label>/ (keeping the stick's folders), soundfonts to library/soundfonts, MIDI files to library/midi, tracks to library/exports (the music player lists them), projects through the exporter's bundle import. exportEntry() goes the other way, into the stick's standard folders (a project as a .ravv bundle, through the exporter). Copies run in a worker thread, one at a time, with progress; a copy onto the stick is synced before it counts as done.

    importAll() queues every file of a kind in a folder of the stick (and its subfolders) that the device does not have yet: one copy after another, counted by batchDone of batchTotal, then one rescan and one finished() at the end; cancelBatch() stops after the copy under way. Kind labels are translated again on a language change. GUI thread only; the walk and the copies run on worker threads.

    [signal] void UsbLibrary::finished(const QString &kind, const QString &name, bool ok, const QString &message)

    Imports every file of kind the stick holds in the folder browse (an entry's browse path; empty for the whole kind) and under it that the device does not have yet, one after the other. Returns how many were queued: 0 when there is nothing new or a copy is under way.

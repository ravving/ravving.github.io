    Detailed Description

    Everything goes through the system's existing interfaces:

    • brightness: the panel's backlight (/sys/class/backlight), saved in the settings and restored at start;
    • output level: the Z2's output amplifier (the jacks' level, LM4811 steps) through zyncoder (ZynthboxBridge::setOutputLevel()), saved and restored the same way;
    • Wi-Fi: wifi (Wifi);
    • Bluetooth: bluetoothctl's power; unavailable while the service is not running;
    • vitals: CPU load (/proc/stat), the SoC temperature (thermal zone 0), the free storage of the user data.

    The address, Bluetooth and vitals are polled every 2 s (Wi-Fi at its own pace) only while active is set. System commands run asynchronously (runCommand()). On a desktop run they read as unavailable.

    [explicit] DeviceControls::DeviceControls(ZynthboxBridge *bridge, QObject *parent = nullptr)

    Finds the backlight, puts back the saved brightness and output level, and reads the address and vitals once, with the given parent. bridge reaches the output amplifier; null on a desktop.

    [invokable] void DeviceControls::setBluetoothOn(bool on)

    Switches Bluetooth's power on when on is true, off otherwise (bluetoothctl power); the state reads switching until the command ends. Ignored while unavailable or switching.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void DeviceControls::switchToZynthbox()

    Hands the device to zynthbox-qml for this session (default-app.sh run zynthbox); the UI that starts at boot stays as it is. ravving stops as zynthbox-qml starts; the script moves itself into a transient unit first, so it survives that.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void DeviceControls::vitalsChanged()

    Emitted when the CPU load, temperature or storage changed.

    Note: Notifier signal for properties cpuLoad, storageFree, storageTotal, and temperature.

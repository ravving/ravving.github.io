    Detailed Description

    The repository it writes is the one GitCommandSnapshotStore writes (the same objects, references and messages), so either reads it, and so does git. Every libgit2 object is held by a guard that frees it on the way out of the call, whatever the path; every failing call reports libgit2's own message through lastError(). The library is initialised for the store's lifetime (reference-counted by libgit2). housekeep() packs in process too (libgit2's pack builder), so no child is started for it either: forking ravving's large process for a git program stalled the audio.

    [override virtual] void LibGit2SnapshotStore::housekeep()

    Reimplements: SnapshotStore::housekeep().

    In process, at the calling thread's priority: the loose objects a branch still reaches go into a new pack (libgit2's pack builder, deltas against each other), then every loose object goes, the packed ones and those no branch reaches (a trail removed or cut by the limit). Once there are eight packs or more, everything reached goes into one pack and the old ones go, so what no branch reaches leaves the packs too. Nothing is dropped when the walk or the pack fails.

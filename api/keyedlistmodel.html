    Detailed Description

    Give it a list of maps (items, a QVariantList from the backend or a JS array) and the key field that names a row. Each new list is matched against the current rows by key: a row that stays keeps its delegate (and its place under the finger), a changed one gets dataChanged, new rows are inserted, missing ones removed and moved ones moved. Setting the whole list again (a rescan, a filter) does not rebuild the view as a plain array model does.

    
 ListView {
     model: KeyedListModel { key: "path"; items: usb.entries("samples") }
     delegate: Rectangle { required property var modelData; required property int index }
 }

    Each map's fields are roles (a delegate may declare required property string name), and modelData is the whole map, so a delegate written for an array model keeps working. The roles are the fields seen so far: a list with a field never seen resets the model once to add it, and the roles only grow, so lists that alternate row shapes (folders and files) do not reset each time. Without a key, or with keys that are missing or not unique, rows are matched by position (a changed row is a dataChanged, extra rows are inserted or removed at the end).

    Registered in the Ravving QML module.

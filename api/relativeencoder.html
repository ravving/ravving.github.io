    Detailed Description

    An endless knob sends a change, not a position: read as a position (0 to 127), its "one up" and "one down" would jump a value between two far-apart places. decode() turns a value into the change it means, by the knob's Mode.

    accelerate() multiplies a single tick by how fast the knob turns: the ticks of the same way within the last WindowMs. Counting ticks over a window, rather than timing the gap between two, keeps the speed right over Bluetooth, which delivers a few ticks at once every connection interval. A knob that already sends bigger changes when turned fast (Mackie Control's V-Pots may) is taken as it is. One per knob; GUI thread only.

    Member Function Documentation

    int RelativeEncoder::accelerate(int delta, qint64 nowMs)

    Returns delta, a change decode() gave at nowMs (a monotonic clock in milliseconds), with the speed's acceleration: a single tick counts once while the knob turns slowly (up to three ticks in WindowMs, this one included), twice from four, and once more for every two further ticks in the window, up to MaxFactor (twelve). A change of more than one tick, or one back the other way, counts as it is.

    [static] int RelativeEncoder::decode(RelativeEncoder::Mode mode, int value)

    Returns the change the CC value (0 to 127) means for a knob of mode: positive up (clockwise), negative down, 0 for no change (a 0, or 64 in OffsetBinary).

    [static] std::optional<RelativeEncoder::Mode> RelativeEncoder::modeNamed(const QString &name)

    Returns the Mode named name as data/midi-devices.json's knobs says it (sign-magnitude, twos-complement, offset-binary), none for any other.

    void RelativeEncoder::reset()

    Forgets the ticks: the next one counts once.

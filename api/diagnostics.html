    Detailed Description

    Every component runs its own checks (at start, and whenever something fails or recovers) and reports here through Issues::report() and Issues::clear().

    An issue is a map with id, component and its translated componentLabel, severity, title, detail, suggestion, action and its actionLabel, since (the ISO time of the first report) and count (the reports since). The severities are error (something does not work), warning (it works worse or will stop) and notice (informational, no action needed). The actions are restart (ravving), unset-gdb (the gdb aid off, then restart) and reboot.

    Reporting an id again updates it and increments its count; clear() removes it when the component sees it recovered; dismiss() hides it while its detail stays the same, and it comes back when the detail changes.

    log keeps the last 40 warnings ravving printed (the message handler in main.cpp feeds note()). report() and note() may be called from any thread; they are queued to this object's thread. One instance, created by main() (instance()).

    Member Function Documentation

    [explicit] Diagnostics::Diagnostics(QObject *parent = nullptr)

    Constructs the issue registry with the given parent; it becomes instance().

    [invokable] void Diagnostics::act(const QString &id)

    Runs the action of the issue id: restart restarts ravving's service, unset-gdb removes RAVVING_GDB from the user manager's environment and restarts, reboot reboots the device.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Diagnostics::clear(const QString &id)

    Removes the issue id, for a component that sees it recovered.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Diagnostics::dismiss(const QString &id)

    Hides the issue id; it returns when it is reported with another detail.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [static] Diagnostics *Diagnostics::instance()

    Returns the Diagnostics instance main() created, or nullptr before it exists or after it is destroyed.

    [invokable] QVariantMap Diagnostics::issue(const QString &id) const

    Returns the issue id, or an empty map when there is none; for tests and scripts.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Diagnostics::note(const QString &text)

    Keeps the warning text in log. Thread-safe: from another thread it is queued.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [invokable] void Diagnostics::report(const QString &id, const QString &component, const QString &severity, const QString &title, const QString &detail = QString(), const QString &suggestion = QString(), const QString &action = QString())

    Reports the problem id, found (or found again) by component, at severity, with its title, detail, suggestion and action (see the class description). A dismissed issue with the same detail stays hidden. Thread-safe: from another thread the report is queued. Also logs a line to the journal.

    Note: This function can be invoked via the meta-object system and from QML. See Q_INVOKABLE.

    [signal] void Diagnostics::reported(const QString &severity, const QString &title)

    Emitted for a new error or warning, or one whose severity rose, with its severity and title.
